# raw_curve_archive_v1

This independent track retains raw C2 rho-mu data only. It does not rerun or
modify the equilibrium solver, Maxwell logic, hybrid policy, reference
promotion, or transport code.

## Scope

The producer is `independent_oracle` at every exact `(xi,T_MeV)` coordinate
present in the C2 `phase_grid_convergence` artifact with `axis=rho`. The
coverage is an exact coordinate set, not a Cartesian completion. The audited
C2 source currently contains 93 xi values and 10,458 unique finite
`(xi,T_MeV)` coordinates.

The numerical checkout is fixed to calculation SHA
`3c5f6b3c9bd535cff7657364dadb2efc31f2ea48`. The audited postprocess context is
SHA `67d73f871578e35759c08b3c75200c51646cf6cd`. The registered audit run is
`31941614867`; the C2 grid source run is `31862752226`. The latter is a grid
and provenance source only: it has no raw `production_eval` files and cannot
recover historical curves.

## Curve schema

`raw_curve_archive_v1` stores one UTF-8 CSV for each `(xi,T_MeV)`. Each source
CSV keeps all 28 columns emitted by the Trho raw production scan:

- Coordinates: `T_MeV` in MeV, `rho` in `rho/rho0` with `rho0=0.16 fm^-3`,
  and dimensionless `xi`.
- Chemical potentials and constituent masses use MeV.
- Pressure and energy use `fm^-4`; entropy and quark densities use `fm^-3`.
- Mean-field and Polyakov-loop fields retain the model output units and
  naming emitted by the source.
- `iterations` is a count, `residual_norm` is solver-defined, and
  `converged`/`message` retain source status.

Every curve must contain the complete `rho=0:0.003125:4` set, 1,281 points.
The source may be written in descending or ascending rho order, but no point
is dropped, interpolated, or regenerated by the archive layer.

## Provenance and retention

Each shard writes `raw_curve_source_manifest.json` plus its SHA-256 sidecar.
The manifest records the method, exact source artifact and run, calculation
SHA, source postprocess/workflow SHA, audit SHA, C2 grid manifest and hash,
solver controls, and the fact that no phase or higher-order postprocess ran.

The archive contains:

- `curves/`: the full byte-preserving curve set;
- `curve_index.csv`: one provenance row per full curve;
- `representative_index.csv`: references into `curve_index.csv`, never a
  separate representative-only data product;
- `source_manifests/`: copied source manifests and their hash sidecars;
- `archive_manifest.json` and `archive_manifest.sha256`.

The strict merge gate requires the actual curve-key set to equal the expected
C2 coordinate set. A partial archive is marked `partial_only` and cannot be
uploaded by the production workflow. `restore_curve_bytes` rechecks the
indexed SHA-256 before returning the original bytes.

## Canonical external archive

The published, immutable raw-data copy is the Zenodo record
[10.5281/zenodo.21980679](https://doi.org/10.5281/zenodo.21980679), record
[21980679](https://zenodo.org/records/21980679), version
`raw_curve_archive_v1`. The repository intentionally keeps the contract and
the machine-readable [external archive pointer](external_archive_pointer.json)
instead of committing the 1.88 GB ZIP.

The exact archive is
`pnjl-raw-curve-archive-issue130-c2-oracle-raw-v1.zip`, 1,879,467,478 bytes,
with SHA-256
`467be7fb1075d1a5f0de3dd0d8afe29d9206a156c0ca7135a1e50967a4f18ccc`. Zenodo
also stores the matching `.sha256` sidecar. The pointer records the source
run/artifact, calculation SHA, audited postprocess SHA, raw-production
workflow SHA, manifest requirements, and retention policy.

To restore the archive, download both Zenodo files, verify the outer ZIP with
the sidecar, extract it without reserialization, and run the `validate-archive`
command recorded in `external_archive_pointer.json`. That validation checks the
inner archive manifest, all curve and source-manifest hashes, exact C2 coverage,
and representative-index references. A manual GitHub Actions check is available
as `PNJL raw curve archive - Zenodo restore verification`; it performs the same
full validation and one byte-preserving sample restore.

## Recovery audit

The Python tool can audit an existing artifact without invoking Julia:

`python scripts/analysis/pnjl_raw_curve_archive.py assess-source-recovery \
  --source-root <downloaded-artifact-root>`

The current C2 aggregate and shard artifacts return `not_recoverable` for raw
curves because `production_eval` was not retained. The new
`pnjl-raw-curve-archive.yml` workflow reconstructs only the raw source at the
highest-precision Oracle settings and then builds the strict archive.
