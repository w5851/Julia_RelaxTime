# 科研分析与实验记录

用于整理已有科研结果、记录实验事实，以及保存隔离文献复现的分析依据。普通结果讨论无需建立完整分析包；任务包含留存时，在已有职责目录内完成，不重复维护多份进度记录。

## 分析与证据

- 围绕具体问题读取相关数据、诊断量和来源，核对单位、字段/坐标对应、缺失点、失败状态及影响判断的精度证据。复用有效记录，输入变化时只复核受影响部分。
- 区分直接观察、贡献分解与机制解释。机制假说注明待检验部分；支持机制的证据应能区分候选解释，可来自解析推导、受控比较、灵敏度、极限或定点诊断。
- 选择足以回答问题的派生量和图表。整理已有结果不自动授权新数值生产或扩大扫描；需要补计算时，说明具体缺口并沿用任务范围。
- 历史结果按其版本和物理口径比较。不能用重新标记、隐藏插值或忽略失败点消除差异；文献明示、直接推导和自行选择的约定分别说明。

## 运行事实与当前结论

| 内容 | 维护方式 |
| --- | --- |
| 运行事实、原始证据、当时判断 | 保留原记录；纠错关联原条目并说明原因 |
| 当前结论、未决问题与阅读摘要 | 在已有未冻结入口原位更新，链接支持它们的证据 |
| 实验索引 | 可去重、分组和整理链接，保持原运行与证据可定位 |

以有意义的实验或批次为单位，记录运行标识、日期、目的、本次参数/方法差异、结果位置及新增观察。已有 manifest 或配置能表达的命令、版本和参数直接引用，补齐缺失的复现信息即可。

写入前按运行标识定向检查已有记录。同一次运行不重复建条目；没有新增信息的重复尝试可按批次汇总，保留标识、状态和必要失败详情。重要失败、反例及未对齐结果不能因汇总而丢失。下一步维护在已有计划位置，不作为每条历史记录的固定结尾。

历史保留不要求当前摘要持续追加，也不禁止为查重和纠错读取旧记录。已冻结或 hash 绑定的文件保持字节不变，后续解释放在外部索引或说明中。

## 按需留存

优先更新同主题已有入口；新分析包按[分析目录约定](../README.md)放在 `docs/analysis/<domain>/<case>_analysis/`。主说明写清问题、方法、结论范围、来源和未决事项。图表、独立日志、事实表或陈述到证据的映射只在阅读与复用需要时增加，不固定套用全部目录或章节。

支撑长期结论的证据应能恢复以下信息，可分布在已有说明、配置和 manifest 中：

- 输入和来源定位，包括文献版本、页码/图表/公式、取点及校准依据；
- 实际生成代码与环境，跟踪代码用明确版本，未提交代码或隔离脚本保留可恢复差异/快照；
- 有效参数、运行方式、关键输出及其对应关系；
- 已执行的核验、比较误差、重要失败和结论的适用范围。

临时目录不能成为长期结论的唯一来源。留存隔离实验时，保存支持判断所需的最小输入、源码快照、配置和关键结果；已有持久证据直接引用。大体积输出可留在已约定的结果目录或外部档案，说明恢复路径，不能仅记录未来会失效的临时链接。遵循[交付物管理](../../dev/项目交付物定位与管理规范.md)的版本与完整性规则，不要求每次探索建立新的 hash 协议。

复用现有分析脚本；本次范围内新增的可维护分析逻辑放入 `scripts/analysis/`。冻结的独立复现代码可以作为研究快照随证据保存，不自动变为稳定计算 API。

## 核验与后续使用

新增或修改派生计算时实际运行并检查单位、点位对应、失败语义和输出可读性；纯文字或链接修改做相应检查。留存前确认结论所需材料确实可访问、代码版本可恢复、引用和适用 hash 一致。

分析记录本身不授予源码合入、基线变更、正式生产或论文使用资格。验证目标按[validation 准入规则](../../../tests/validation/README.md)区分 acceptance、evidence 和 analysis；正式产物沿用专题 SOP，文献到实现的公式与来源边界见[项目协议](literature_to_implementation_protocol.md)。
