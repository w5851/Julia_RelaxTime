# Phase E4 稳定BW与PhaseE3比较口径说明

更新日期：2026-05-02

目的：正式定义当前 `stable / BW / Phase-E3` 三条链的最小比较口径，并记录在同一 `meson workflow / continuation` 口径下的首轮并排比较结果，作为是否结束 Phase E、是否立即转入 Phase F 的判断依据。

相关脚本：

- `scripts/analysis/relaxtime/compare_meson_density_regimes_phase_e4.jl`

相关输出：

- [meson_density_phase_e4_compare.csv](../../../data/outputs/results/relaxtime/analysis/meson_density_phase_e4_compare.csv)

---

## 1. 为什么需要 E4

到 Phase E3 为止，项目里已经同时存在三条数密度链：

1. `stable`
2. `BW`
3. `Phase-E3` 最小相移双积分

如果没有正式比较口径，就会出现两个问题：

- 不知道这些结果是否可直接放在同一张图上解释
- 不知道某种差异到底是“物理上应当出现”，还是“当前实现仍未收口”

因此 E4 的角色不是再实现一套新公式，而是建立一个**并排比较与阶段判断**的基准面。

---

## 2. 当前三条链分别代表什么

### 2.1 `stable`

- 代表稳定粒子极限
- 只使用壳上质量 `m_pi / m_K`
- 不包含有限宽度与连续谱

它当前应被视为：

- 基线
- 低复杂度对照对象

### 2.2 `BW`

- 代表最小 BW 质量展宽代理
- 用有限宽度对稳定粒子极限做最小展宽修正
- 仍然不是严格 BU 相移实现

它当前应被视为：

- 稳定极限与严格 BU 之间的过渡台阶
- 检查“有限宽度进入后，结果是否开始偏离 stable”的最小诊断层

### 2.3 `Phase-E3`

- 代表当前最小相移双积分实现
- 基于 `delta_M(omega,q) = arg D_M(omega+i eta,q)`
- 当前默认口径：
  - `qmax = 12`
  - `q_nodes = 48`
  - `omega_max = 10`
  - `omega_nodes = 48`

它当前应被视为：

- 严格 BU 主线上的**第一个正式 workflow 版本**
- 但还不是“最终可解释版本”

---

## 3. 当前正式比较口径

本轮比较固定：

- 同一组 `T = 208:2:220 MeV`
- `muB = 0`
- `xi = 0`
- 同一 continuation 主链
- 同一 `meson_point`

比较脚本先求一次：

```text
Models.solve_gap_and_meson_point
```

然后在同一个 `meson_point` 上分别计算：

- `stable`
- `BW`
- `Phase-E3`

因此当前比较结果不会混入“不同 workflow 求到了不同介子质量分支”的漂移。

---

## 4. 当前至少已经确认的“应当出现的差异”

E4 的原始验收要求是：

- 至少明确一个“应当出现的差异”

截至当前，这一点已经满足。

### 4.1 `BW` 应当比 `stable` 更接近，但只出现有限偏移

当前比较结果显示：

- `kpi_stable`：约 `0.57 -> 0.64`
- `kpi_bw`：约 `0.58 -> 0.68`
- `delta_kpi_bw`：约 `+0.01 -> +0.04`

这与 Phase D3 的判断一致：

- BW 的作用应当是对 stable 做**有限宽度修正**
- 而不是把结果整体推到完全不同的数量级

因此：

- **`BW` 相对 `stable` 的小到中等偏移，是当前“应当出现的差异”。**

### 4.2 `Phase-E3` 不应再被当作“只是 BW 的小修正”

当前比较结果显示：

- `kpi_phase`：约 `1.37 -> 1.40`
- 相对 `kpi_stable` 的偏移约 `+0.76 -> +0.80`
- `n_pi_phase / n_pi_stable`：约 `7.8 ~ 8.2`
- `n_K_phase / n_K_stable`：约 `17.1 ~ 19.7`

这说明：

- 当前 `Phase-E3` 结果已经不属于“BW 的轻微延伸”
- 它与 stable / BW 之间存在**数量级级别的结构差异**

这同样是一个“应当被 E4 正式记录的差异”，因为它直接决定了后续阶段判断。

---

## 5. 这意味着什么

### 5.1 E4 作为“比较口径建立”已经完成

因为当前已经明确：

- 哪三条链在比较
- 各自代表什么
- 至少一个应当出现的差异是什么
- 并且已经给出同口径并排 CSV

所以从任务单字面验收看，**E4 已经完成**。

### 5.2 但这不等于“Phase-E3 结果已经可以直接拿去做最终解释”

当前更关键的判断是：

- `Phase-E3` 与 stable / BW 的差异已经大到不能被当作“小修正”
- 这类差异可能意味着：
  1. continuum / off-shell 贡献在当前最小口径下确实非常强
  2. 或当前最小口径还没有完成更严格 BU 收口，因而暂时不能直接当作最终物理结果解释

换句话说：

- **E4 完成的是“比较口径建立”**
- **但并没有自动完成“物理解释收口”**

---

## 6. 对 Phase E / Phase F 的阶段判断

当前更稳妥的阶段判断应是：

1. Phase E 的 `E1-E4` 最小任务已经全部落地
2. 但比较结果表明，当前 `Phase-E3` 与 stable / BW 的差异过大
3. 因此当前不宜立刻进入 Phase F 做正式图形集与结果叙事

更合理的后续顺序应是：

1. 保留 E4 已完成的状态
2. 把“是否需要继续更严格 BU 收口”提到当前优先级更高的位置
3. 暂缓把当前 Phase-E3 扫描结果直接包装成 Phase F 图形主结果

---

## 7. 当前判断一句话版

- **Phase E4 已完成比较口径建立；但比较结果显示当前 Phase-E3 与 stable / BW 存在数量级级别差异，因此当前更合理的下一步不是直接进入 Phase F，而是优先继续更严格 BU 收口。**
