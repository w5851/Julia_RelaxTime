# 老项目功能覆盖审计与 Julia 功能补齐路线

更新日期：2026-03-08

> 目的：在继续扩充 validation 之前，先审计 legacy Fortran / C++ 已具备而 Julia 主线尚未完整覆盖的能力，识别“真缺功能”与“仅缺工程化出口”的边界，并整理现有参考文献可支持的物理语义与尚缺公式来源。

---

## 1. 背景与目标

- 当前仓库已经具备：平衡态求解、相图/crossover、弛豫时间、`eta`、`zeta`、`sigma`、部分通道级散射与派生输出。
- legacy Fortran 与 legacy C++ 还稳定产出一组更高层的输运量与比值量，其中一部分尚未在 Julia 主线形成统一实现或标准输出。
- 如果这类量本身就是 Julia 物理能力缺口，那么优先级应高于“把更多 legacy 数据纳入 validation”；因为没有主线实现时，validation 只能停留在外部对照而不能形成正式产品能力。

本文档目标：

- 明确 legacy 功能面与 Julia 当前覆盖面的差异。
- 把差异分成“真缺功能”与“工程化缺口”两类。
- 对真缺功能给出物理意义、legacy 代码级定义与 Julia 补齐路线。
- 评估用户指定参考文献“高雪艳博士论文”能否提供直接公式依据。
- 作为 `kappa` 正式实现前的执行任务单，约束 helper、kernel、测试与验收顺序。

---

## 2. 范围与非范围

### 2.1 范围

- legacy Fortran / C++ 高层输运输出能力审计。

- 参考 thesis 对这些量的可用证据与证据缺口说明。
- 后续实现任务单、验收与风险说明。

### 2.2 非范围

- 本文档不直接落地代码实现。
- 本文档不直接改造 `tests/validation/` 结构；该项另见已存在的 validation 设计文档。
- 本文档不把所有 legacy 输出都视为必须补齐的主线 API。
- 本文档不把 thesis 中未明确出现的输运公式强行解释为已找到文献依据。

## 4. 真缺功能的物理意义与 legacy 定义

本节以 legacy Fortran `Relaxtime_fortran/codes/main/coefficients_tmu.f90` 为代码级单一事实来源。

### 4.1 `kappa_BB`

- 物理意义：重子守恒荷对应的扩散输运系数，描述重子数流对热力学驱动力的扩散响应。
- 在 legacy 中，它不是简单的“某 flavor 密度积分”，而是经过流体对流项投影后的守恒荷扩散核。
- legacy 代码级定义可写成：

$$
\kappa_{BB}
=
\sum_{j,k}
\frac{N_c\,\tau_{jk}}{3\pi^2}
\int dp\,\frac{p^4}{E_k^2}
F_{jk}(p)
\left(B_{jk}-\frac{n_B E_k}{\epsilon+P}\right)^2
$$

其中：

- $j$ 表示 quark / antiquark 分支；$k$ 表示 flavor。
- $F_{jk}(p)$ 是 legacy 代码里的占据相关核 `arrFF(j,k)`。
- 投影项 $n_B E / (\epsilon + P)$ 表明该量处于守恒流相对整体能流的扩散通道，而不是单纯静态 susceptiblity。

### 4.2 `kappa_QQ`

- 物理意义：电荷守恒流的扩散输运系数，刻画净电荷流的扩散响应。
- 它与 `sigma` 有关但不等价：`sigma` 更接近电导率；`kappa_QQ` 是电荷扩散通道的 Onsager 系数式量。
- legacy 代码级定义为：

$$
\kappa_{QQ}
=
\sum_{j,k}
\frac{N_c\,\tau_{jk}}{3\pi^2}
(4\pi\alpha_{em})
\int dp\,\frac{p^4}{E_k^2}
F_{jk}(p)
\left(Q_{jk}-\frac{n_Q E_k}{\epsilon+P}\right)^2
$$

- 相比 `kappa_BB`，其关键差别是守恒荷投影换成电荷，并显式带有电磁耦合因子 $4\pi\alpha_{em}$。

### 4.3 `kappa_SS`

- 物理意义：奇异守恒荷的扩散输运系数，描述 strange charge 的扩散响应。
- legacy 代码级定义为：

$$
\kappa_{SS}
=
\sum_{j,k}
\frac{N_c\,\tau_{jk}}{3\pi^2}
\int dp\,\frac{p^4}{E_k^2}
F_{jk}(p)
\left(S_{jk}-\frac{n_S E_k}{\epsilon+P}\right)^2
$$

- 这说明 Julia 若补齐 `kappa_BB` 的统一积分骨架，通常可以顺带以“更换守恒荷投影”的方式统一生成 `kappa_QQ` 和 `kappa_SS`。

### 4.4 `lambda`

- 物理意义：热导率，衡量介质对温度梯度诱导热流的传输能力。
- legacy 并未单独定义一套新的动量积分核，而是先得到 `kappa_BB`，再通过热力学组合关系构造：

$$
\lambda
=
\kappa_{BB}
\left(\frac{\epsilon+P}{n_B T}\right)^2
$$

- 这意味着 Julia 要补 `lambda`，前置条件是：
  - 已能稳定计算 `kappa_BB`
  - 已有一致的 `\epsilon`、$P$、$n_B$、$T$ 定义和单位链
- 这也解释了为什么 `lambda` 应与 `kappa_BB` 作为同一立项处理，而不是拆成两个独立 feature。

### 4.5 派生比值的意义

- `Lorentz = lambda / (sigma / T)`
  - 热导与电导的相对量级诊断；是否满足类似 Wiedemann-Franz 型关系需要单独物理解读，但代码层它只是派生比值。
- `R_etasig = (eta / s) / (sigma / T)`
  - 剪切粘滞与电导响应的相对强弱比较。
- `Pr = eta * c_p / (lambda * rho_mass)`
  - Prandtl 数，衡量动量扩散与热扩散的相对重要性。
- `RI = 4 / (eta / rho_mass)`
  - legacy 文件中直接这样定义，但仅从代码名难以唯一确认其标准物理命名与推导来源；需要额外公式来源支持。
- `zeta_eta = zeta / eta`
  - 体粘滞与剪切粘滞的直接比值。

### 4.6 它们不是静态涨落或磁化率

需要明确区分三类容易混淆的记号：

- thesis 中的 `\chi_{BQS}` 是守恒荷广义磁化率，也就是压强对 `(\mu/T)` 的热力学导数。
- thesis 中的 `\kappa\sigma^2` 里的 `\kappa` 是峰度，不是输运系数 `kappa_BB`。
- legacy Fortran 中的 `kappa_BB / kappa_QQ / kappa_SS` 是带弛豫时间 `tau` 的输运扩散系数。

二者不是同一个量，理由如下：

- [ ] Fortran `kappa_*` 显式乘了 `arrTau(:,:)`，说明它们依赖散射与弛豫时间尺度；静态磁化率 `\chi` 作为平衡态热力学导数，不应显式含 `tau`。
- [ ] Fortran `kappa_*` 的积分核是 `p^4 / E^2` 与流体投影项 `(q - n E / (\epsilon + P))^2`；这对应流的输运响应，而不是配分函数对化学势求导。
- [ ] thesis 中守恒荷涨落的定义是 `\chi_{ijk}^{BQS} = \partial^{i+j+k}(P/T^4) / \partial(\mu_B/T)^i \partial(\mu_Q/T)^j \partial(\mu_S/T)^k`，本质上是静态热力学 susceptibilities。
- [ ] thesis 中累积量满足 `C_{ijk}^{BQS} = V T^3 \chi_{ijk}^{BQS}`，描述的是事件涨落/关联涨落，不是电荷扩散流或热流。
- [ ] Fortran 只实现了对角的 `BB / QQ / SS` 三个输运通道，没有实现 `BQ / BS / QS` 这类“关联涨落”混合 susceptibilities 的结构。

更合理的理解是：

- `kappa_BB / kappa_QQ / kappa_SS` 属于守恒荷输运系数。
- `\chi_B, \chi_Q, \chi_S` 或 `\chi_{BQS}` 属于静态涨落/关联涨落。
- 两类量在流体或动理学框架中可能通过 Einstein/Onsager 型关系间接联系，但不能直接等同。

## 11. 风险与回退策略

- 风险 1：如果只依赖 legacy 代码反推，可能复制数值口径但缺少正式物理注释。
  - 回退：先以 internal/experimental 形式实现，待文献锚定后再升格为正式 API。
- 风险 2：`n_B -> 0` 附近 `lambda = kappa_BB ((\epsilon+P)/(n_B T))^2` 可能出现数值放大或奇异行为。
  - 回退：在接口层显式限制适用区域，并单独设计 `mu_B = 0` 邻域测试策略。
- 风险 3：`RI` 的物理意义不清，直接实现会把 legacy 命名错误带入主线。
  - 回退：将 `RI` 留在 debug / legacy compare 层，暂不进入正式导出列表。
