# Solver 五大痛点深层治理总任务单（PR-D/E/F）

## 1. 背景与目标

- 背景：`solver/` 已具备完整功能，但仍存在种子/残差/治理/入口/文件结构多通道并行，导致心智模型复杂、变更风险高。
- 目标：围绕 5 个高优先级痛点，按可独立合并的 PR 逐步收敛到“单一职责 + 单一事实来源 + 单一路径语义”。
- 本任务单定位：治理型重构，不追求新增物理功能。

## 2. 五个痛点与治理主轴映射

- [x] P1 种子重复维护（`GapSolver.jl` vs `SeedStrategies.jl`） -> 主轴 A：Seed SoT（single source of truth）。
- [x] P2 残差三套路径并行（`gap_residual` / `gap_core_residual!` / 局部 residual） -> 主轴 B：Residual Spine（统一残差脊柱）。
- [x] P3 FixedMu 与非 FixedMu 入口分裂 -> 主轴 C：Entry Unification（入口统一）。
- [x] P4 attempt/selector 治理机制多套并行 -> 主轴 D：Governance Unification（治理统一）。
- [x] P5 `ConstraintSolver.jl` 过载 -> 主轴 E：Vertical Slice（按模式纵切拆分）。

## 3. PR 拆分策略（建议）

- [x] PR-D（先做）：主轴 A + 主轴 B（种子与残差先统一，先消除行为漂移根源）。
- [x] PR-E（其次）：主轴 C + 主轴 D（入口与治理语义单路化）。
- [x] PR-F（最后）：主轴 E（结构拆分与可维护性收口）。

## 4. 总体验收（项目级 DoD）

- [x] 任一 mode 的求解行为在入口层不再依赖“隐藏分支语义”。
- [x] 种子来源、残差来源、治理选择来源均能定位到单一实现点。
- [x] 新增/改动约束时，不需要跨 3+ 文件重复改同一语义。
- [x] `tests/unit + tests/regression` 关键集合稳定通过，且回归点覆盖 5 类模式。
- [x] active 文档状态与实现一致，完成后可归档。

## 4.1 反表面化治理约束（必须同时满足）

- [x] 不接受“仅抽 helper/改命名/搬代码但语义不变”的伪治理结果，必须减少并行语义通道数量。
- [x] 每个痛点需有“唯一实现点”与“禁止新增平行实现点”声明，并由测试守护。
- [x] 每个 PR 必须给出“删除了哪些重复路径”的清单，而不只是“新增了什么封装”。
- [x] 对外行为兼容不是唯一目标，内部架构可证明更简单（调用链更短、职责边界更清晰）。
- [x] 对关键 mode（FixedMu/FixedRho/FixedAsymmetricRho/FixedEntropy/FixedSigma）均给出一致性证据。

## 5. 里程碑

- [x] M1：PR-D 合并（SoT 与 Residual Spine 建立）。
- [x] M2：PR-E 合并（统一入口与治理语义）。
- [x] M3：PR-F 合并（结构可维护性完成收口）。

## 6. 架构完成态判据（收口标准）

- [x] Seed：默认 seed 候选的定义、排序、去重、扩展在单点维护；调用层只消费，不再自建默认池。
- [x] Residual：同一 mode 的残差表达在主链只有一套实现；其他位置只能组合调用，不可复制表达。
- [x] Entry：`solve_constraint` 的 mode 行为语义一致，调用者无需记忆“特殊路径”。
- [x] Governance：attempt 执行、success 判定、selector 选择是单条管线，不存在二次筛选。
- [x] Structure：`ConstraintSolver` 从单文件巨石转为按 mode 可独立维护的纵切结构。

## 7. 当前结论（2026-04-08）

- PR-D / PR-E / PR-F 均已合并：`#65` / `#66` / `#67`。
- 五大痛点主轴治理目标已完成。
