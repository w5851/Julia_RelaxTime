# 相图 API 三层视图与导出索引治理任务单

更新日期：2026-03-10

> 目标：按照当前 API 文档治理策略，为相图主题建立“面向用户入口 / 算法核心 / 导出 API 全集”三层视图，完成新架构路径下的 phase 子目录导航、旧路径兼容跳转，以及导出 API 全集的脚本化生成闭环。

---

## 1. 背景与问题定义

`src/models/phase/` 已成为相图实现的单一事实源，公开调用面主要经由 `Models` 聚合入口暴露；但当前相图文档仍存在以下问题：

- phase 主题文档仍主要停留在 `docs/api/pnjl/` 历史平铺路径下，而新治理目标已转向 `docs/api/models/phase/`；
- 已有文档偏算法页，缺少统一的“面向用户入口”页面；
- 公开导出接口的完整性无法靠人工文档证明；
- 旧页面仍含历史源码路径或历史导航口径；
- 已确认的文档治理规则尚未在相图主题落地：
  - 三层视图组织；
  - `导出 API 全集` 必须自动生成；
  - 自动化层由 `scripts/dev/generate_api_export_index.jl` 支撑。

本任务单替代旧的“补齐与目录重构”版本，作为相图 API 文档治理的唯一活动任务单。

---

## 2. 范围与非目标

### 2.1 范围

- 相图主题文档入口与导航治理；
- 相图主题的“面向用户入口”与“算法核心”人工文档；
- 相图主题的“导出 API 全集”自动生成页；
- 旧平铺页面到新目录的兼容跳转；
- 导出索引脚本在相图主题上的可用化。

### 2.2 非目标

- 不在本任务中引入 Documenter.jl；
- 不在本任务中重命名整个 `docs/api/` 体系；仅对 phase 主题优先迁入 `docs/api/models/phase/`；
- 不在本任务中重写 phase 相关实现代码；
- 不把所有 phase 内部算法都提升为对外稳定入口。

---

## 3. 设计原则

- **视图优先**：先定义“给谁看”和“看什么”，再决定拆成几页。
- **入口与实现分离**：用户入口页优先写 `Models` 聚合入口，不让读者从深层实现文件起步。
- **算法核心单独成层**：关键判据与算法关系要可读，但不机械抄源码。
- **导出完整性自动化**：公开导出面的完整性由脚本生成页保证，不依赖人工补漏。
- **兼容迁移**：旧路径保留薄跳转说明，不破坏历史链接。

## 4. 相图主题公开 API 基线

### 4.1 面向用户入口候选

- `Models.run_phase_pipeline`
- `Models.find_cep`
- `Models.build_phase_artifacts`
- `Models.resolve_phase_output_target`
- `Models.promote_phase_artifacts`

### 4.2 结果类型候选

- `PhasePipelineResult`
- `CEPResult`
- `PromotionResult`

### 4.3 算法核心候选

- `detect_s_shape`
- `maxwell_construction`
- `detect_crossover`
- `scan_crossover_line`
- `AdaptiveRhoConfig`
- `suggest_refinement_points`
- `merge_rho_values`

说明：

- `面向用户入口` 与 `结果类型` 优先来自 `Models` 聚合导出；
- `算法核心` 允许覆盖未被聚合导出的 phase 子域算法，但它们不自动等价于“首选公开入口”；
- `导出 API 全集` 页必须以脚本生成的公开导出清单为基线，而不是以人工候选列表为基线。

## 6. 自动化策略

### 6.1 现有基础

仓库已提供脚本：

- `scripts/dev/generate_api_export_index.jl`

当前能力：

- 扫描目标 Julia 文件中的 `export` 列表；
- 生成 Markdown 导出索引页；
- 统计导出符号是否已在 `docs/api/` 的非 generated 页面中被提及。

### 6.2 相图主题需要补足的能力

现有脚本适合单文件导出面；相图主题需要解决“导出面跨 `Models.jl` / `entrypoints.jl`，且只取 phase 相关子集”的问题。

本任务内应采用以下路线之一，并在实施时二选一落地：

- **方案 A：脚本增强优先**
  - 为 `generate_api_export_index.jl` 增加相图主题过滤能力；
  - 支持多源文件与按符号过滤；
  - 输出 `docs/api/models/phase/generated/Exports.md`。

- **方案 B：主题配置清单过渡**
  - 增加一个 phase 主题导出清单配置文件；
  - 由脚本读取配置，再生成导出页；
  - 该清单只能描述过滤规则，不允许手工维护全文内容。

阶段 A 决策（2026-03-10，已落地）：

- 采用方案 A，不引入单独配置清单；
- 导出来源固定为 `src/models/Models.jl` 与 `src/models/entrypoints.jl`；
- 过滤集合固定为 phase 主题当前公开导出：
  - `run_phase_pipeline`
  - `find_cep`
  - `build_phase_artifacts`
  - `resolve_phase_output_target`
  - `promote_phase_artifacts`
  - `PhasePipelineResult`
  - `CEPResult`
  - `PromotionResult`
- 已生成基线页面：`docs/api/models/phase/generated/Exports.md`。

### 6.3 生成产物要求

- 输出位置：`docs/api/models/phase/generated/Exports.md`
- 页面头部明确标注“自动生成，不手工维护”
- 至少包含：
  - 导出符号名
  - 来源文件
  - 是否已被人工文档提及
  - 未被提及的符号列表

当前生成命令：

```powershell
julia --project=. scripts/dev/generate_api_export_index.jl \
    --module-file src/models/Models.jl \
    --module-file src/models/entrypoints.jl \
    --include-symbol run_phase_pipeline \
    --include-symbol find_cep \
    --include-symbol build_phase_artifacts \
    --include-symbol resolve_phase_output_target \
    --include-symbol promote_phase_artifacts \
    --include-symbol PhasePipelineResult \
    --include-symbol CEPResult \
    --include-symbol PromotionResult \
    --output docs/api/models/phase/generated/Exports.md \
    --title "Phase Export API Index"
```

## 9. 风险与注意事项

- 若不先确定“导出 API 全集”的来源与过滤规则，后续页面再多也无法证明完整性。
- 若同时保留 `PhaseDiagramWorkflow.md` 与 `phase/Overview.md` 作为主入口，会造成长期维护分叉。
- 若旧页面直接删除而不保留跳转，将破坏已有引用与历史上下文。
- 若导出全集页允许人工维护，后续很快会再次失真。
