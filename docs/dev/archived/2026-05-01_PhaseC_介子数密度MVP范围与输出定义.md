# Phase C：MVP 范围与输出定义

本文对应任务单 `Phase C`，用于在代码实现前锁定当前介子数密度主线的最小问题定义（MVP）。

本文的作用是把“当前要做什么”与“当前明确不做什么”分开，避免在 `Phase D/E` 实现时把现象学扫描、EOS 扩展或更大范围的相图任务混入最小验证主线。

## 1. MVP 的问题表述

当前主线的最小问题定义为：

> 在当前项目已有 PNJL + RPA + 极化函数 / 传播子底座上，先建立 `\mu_B = 0` 下 `\pi/K` 介子数密度与 `K/\pi` 比值的最小可验证链路，先完成稳定粒子极限与必要的 BW 过渡验证，再为 BU 相移实现准备统一的输入/输出口径。

这个定义强调三点：

1. 当前首先要做的是“最小可验证链路”，不是完整 BU 产品化接口；
2. 当前首先验证 `\mu_B = 0` 情形，而不是广义化学势扫描；
3. 当前目标是为 BU 做好主线准备，而不是把 EOS 或碰撞现象学拟合一起并入。

## 2. 当前 MVP 范围

## 2.1 物理范围

当前 MVP 固定为：

1. `\mu_B = 0`
2. 静态、均匀介质
3. 介子道仅限 `\pi` 与 `K`
4. 目标物理量仅限：
   - `n_pi(T)`
   - `n_K(T)`
   - `n_K/n_pi(T)`

### 说明

- 这里的 `n_pi(T)` 与 `n_K(T)` 默认指聚合通道总数密度，具体简并因子口径已在 `Phase B` 固定为 `d_\pi=3`、`d_K=4`。
- 当前阶段默认平衡态最小口径：`μ_u = μ_d = μ_s = 0`，因此 `μ_\pi = μ_K = 0`。

## 2.2 模型与实现范围

当前 MVP 允许复用的项目底座包括：

- [src/relaxtime/MesonMass.jl](../../../../../src/relaxtime/MesonMass.jl)
- [src/relaxtime/PolarizationAniso.jl](../../../../../src/relaxtime/PolarizationAniso.jl)
- [src/relaxtime/MesonPropagator.jl](../../../../../src/relaxtime/MesonPropagator.jl)
- [scripts/relaxtime/run_mott_phase_scan.jl](../../../../../scripts/relaxtime/run_mott_phase_scan.jl)

当前实现边界固定为：

1. 主传播子与极点条件服从现有项目口径 `1 - 4K\Pi = 0`；
2. 稳定粒子极限是第一验证台阶；
3. BW 仅作为过渡验证层；
4. BU 相移实现以后续独立阶段进入，不在当前 `Phase C` 里要求代码完成。

## 3. 最小输出物定义

## 3.1 必需输出物

当前 MVP 至少应提供以下三类结果：

1. `n_pi(T)` 曲线或等价的温度表
2. `n_K(T)` 曲线或等价的温度表
3. `n_K/n_pi(T)` 曲线或等价的温度表

这三类输出可以先以任一形式存在：

- 代码内可重复生成的数组 / 结构化结果
- 脚本输出的 CSV / JSON / 表格
- 基于数值结果生成的图

## 3.2 当前推荐的最小交付形态

在不扩 scope 的前提下，当前推荐最小交付物为：

1. 一个可重复运行的最小数密度计算入口；
2. 一个温度扫描结果表；
3. 一张 `n_pi(T)` 与 `n_K(T)` 对照图；
4. 一张 `n_K/n_pi(T)` 图。

### 说明

- 若当前阶段只到 `Phase D`，则图和结果可以先来自稳定粒子极限；
- 若进一步完成 BW 过渡验证，则可在同图中加入 BW 对照；
- 在 BU 尚未落地前，所有图都必须明确标注属于“验证台阶”。

## 3.3 当前不强制要求的输出

当前 MVP 不强制要求：

1. `K^+/\pi^+` 与 `K^-/\pi^-` 分裂结果
2. 沿冻结线或相变线的二维扫描图
3. 与实验数据的直接拟合图
4. BU 与 BW 的整套大图组

这些都属于后继阶段输出，而非当前最小交付物。

## 4. 当前明确不做的内容

## 4.1 物理范围上不做

当前 MVP 明确不做：

1. EOS / 介子压强扩展
2. 广义化学势扫描
3. 完整 `T-\mu_B` 相图扫描
4. `x = T/\mu_B` 冻结线现象学重建
5. `\mu_\pi(x)`、`\mu_s(x)` 的经验拟合

## 4.2 工程范围上不做

当前 MVP 明确不做：

1. 先设计完整 BU 通用接口再回头验证
2. 在当前阶段并行扩展到所有介子道
3. 在数密度主线未稳定前就引入前端或服务接口
4. 为了兼容未来所有现象学场景而提前做大而全抽象

## 4.3 RS 各向异性当前不扩展的部分

虽然当前项目已有 RS 各向异性底座，但在 MVP 中：

1. 不要求当前就完成各向异性下的介子数密度链路；
2. 不要求当前就把稳定粒子色散关系改写成 `E_M(q,\theta;\xi)`；
3. 不要求当前就完成各向异性 BU 数值积分。

当前阶段只要求保证后续 BU 相移实现时，RS 可以沿 `\Pi \to \mathcal{D} \to \delta_M` 这条链路自然接入。

## 5. 当前 MVP 与后续阶段的接口关系

## 5.1 向 `Phase D` 的衔接

当前 `Phase C` 锁定后，`Phase D` 的任务就非常明确：

1. 先做稳定粒子极限数密度；
2. 核对单位、量级和温度趋势；
3. 再决定是否加入 BW 过渡验证。

## 5.2 向 `Phase E` 的衔接

当前 `Phase C` 锁定后，`Phase E` 的边界也更清楚：

1. 相移实现只需要服务于 `\pi/K` 数密度与 `K/\pi` 比值；
2. 不需要一开始就覆盖冻结线现象学任务；
3. BU 数值积分只需满足当前最小输出物，不必先做全景接口。

## 6. 当前 Phase C 结论

当前主线的最小问题定义已经固定为：

1. `\mu_B = 0`
2. `\pi/K`
3. 静态、均匀介质
4. 输出仅限 `n_pi(T)`、`n_K(T)`、`n_K/n_pi(T)`
5. 先做稳定粒子极限与必要的 BW 过渡验证
6. BU 相移实现作为下一阶段目标
7. EOS、广义化学势扫描、完整相图与冻结线现象学拟合全部后置
