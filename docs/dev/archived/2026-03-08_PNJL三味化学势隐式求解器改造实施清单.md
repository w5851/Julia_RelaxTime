# PNJL 三味化学势隐式求解器改造实施清单

更新日期：2026-03-08

> 目的：把“阶段 B：三味 flavor 化学势隐式求解扩展”细化成可直接执行的实施清单，明确要改哪些文件、增加哪些接口、保持哪些兼容行为，以及测试应按什么顺序补齐。

---

## 1. 改造目标

本清单只解决一个问题：

- 让平衡态解 `x*(T, μ_u, μ_d, μ_s)` 成为稳定的自动微分目标。

本清单不直接实现：

- `χ_{ijk}^{BQS}`
- `C_{ijk}^{BQS}`
- `Sσ` 与 `κσ^2`

但它是这些量进入完整 `B/Q/S` mixed susceptibilities 阶段的前置条件。

补充说明：

- 该求解器改造完成后，susceptibility 层的首版实现应优先以 `P(T, μ_u, μ_d, μ_s)` 的 flavor 导数作为主对象。
- `P/T^4` 的 `T` 缩放建议在导数完成后解析施加，以避免低温区直接除以 `T^4` 带来的额外数值放大。

## 3. 改造边界与兼容策略

### 3.1 必须保持兼容的旧接口

以下接口在本次改造中不应破坏：

- [x] `solve_with_derivatives(T, μ; ...)`
- [x] `solve_pnjl_with_derivatives(T, μ; ...)`
- [x] `create_implicit_gap_solver(model; ...)` 的现有对称 μ 语义
- [x] 所有依赖对称化学势路径的现有相图、crossover、thermo derivative 测试

### 3.2 建议新增而非替换的接口

为避免连带破坏，建议新增一套 flavor-μ 显式接口：

- [x] `create_flavor_mu_implicit_gap_solver(model; ...)`
- [x] `solve_pnjl_with_flavor_mu_derivatives(T, mu_vec; order=1, ...)`
- [ ] 如有必要，再增加 `solve_with_flavor_mu_derivatives(model, T, mu_vec; ...)`

原则：

- 新需求走新接口。
- 旧接口保持“对称 μ 快路径”。

### 3.3 本期不建议做的事情

- [ ] 不把现有 `solve_pnjl_with_derivatives(T, μ)` 直接改成接受 `mu_vec`
- [ ] 不把 `create_implicit_gap_solver(model; ...)` 的默认参数维度从 2 悄悄改成 4
- [ ] 不在本阶段引入 `μ_B, μ_Q, μ_S` 作为求解器原生参数

原因：

- 当前模型热核天然基于 flavor 化学势。
- `B/Q/S` 应放在 susceptibility 层通过链式法则映射，而不是压进平衡态求解器层。

## 5. 实施步骤

### 5.1 Step 0: 明确参数契约

目标：先固定 flavor-μ 版本的参数含义，避免后续接口漂移。

- [x] 约定新接口统一使用 `mu_vec = SVector(μ_u, μ_d, μ_s)`
- [x] 约定外层隐函数参数向量为 `θ = [T, μ_u, μ_d, μ_s]`
- [x] 明确本层不处理 `μ_B, μ_Q, μ_S -> μ_u, μ_d, μ_s` 变换
- [x] 明确一阶导数输出语义为：
  - `dx_dT`
  - `dx_dmu_vec` 或 `dx_dmu` 的 5×3 Jacobian

验收：

- [x] 文档和函数 docstring 中对参数顺序写明，不留猜测空间

### 5.2 Step 1: 新增 flavor-μ 版 implicit solver 构造器

建议新增函数：

- [x] `create_flavor_mu_implicit_gap_solver(model::AbstractPNJLModel; xi, p_num, t_num, kwargs...)`

建议行为：

- `forward_solve_impl(θ)`
  - [x] 读取 `T_fm = Float64(θ[1])`
  - [x] 读取 `mu_vec = SVector{3,Float64}(Float64(θ[2]), Float64(θ[3]), Float64(θ[4]))`
  - [x] 调用现有 `solve_gap(model, T_fm, mu_vec; ...)`
  - [x] 返回 5 维 `state_vector`
- `conditions_impl(θ, x, z)`
  - [x] 读取 `T_fm = θ[1]`
  - [x] 读取 `mu_vec = SVector{3}(θ[2], θ[3], θ[4])`
  - [x] 调用现有 `gap_residual(model, x, T_fm, mu_vec; ...)`
  - [x] 不做任何 `Float64(...)` 强制转换

验收：

- [x] 在固定测试点上，新 solver 能返回 primal 解
- [x] `conditions_impl` 对 `Dual` 输入不报类型错误

### 5.3 Step 2: 新增 flavor-μ 版导数包装

建议新增函数：

- [x] `solve_pnjl_with_flavor_mu_derivatives(T_fm, mu_vec; order=1, ...)`

一阶返回建议：

- [x] `x`
- [x] `dx_dT`
- [x] `dx_dmu_vec`

其中：

- `dx_dT` 是长度 5 的向量
- `dx_dmu_vec` 是 5×3 Jacobian，列顺序固定为 `μ_u, μ_d, μ_s`

二阶返回建议：

- [ ] 先只实现最需要的 Hessian blocks
- [ ] 若直接实现完整二阶，建议命名为：
  - `d2x_dT2`
  - `d2x_dTdmu_vec`
  - `d2x_dmu_vec2`

注意：

- [x] 不要求此步立即暴露完整三阶张量的易用格式
- [x] 先保证内部可计算，再考虑高层易用包装

验收：

- [x] 新函数在 `μ_u = μ_d = μ_s` 时，与旧 `solve_pnjl_with_derivatives` 的 `x` 和 `dx_dT` 一致
- [x] 新函数的对称方向导数组合与旧 `dx_dμ` 一致

### 5.4 Step 3: 对称方向一致性校验 helper

建议增加一个内部 helper，用于测试时把 flavor Jacobian 投影回对称方向：

- [x] `symmetric_mu_direction_derivative(dx_dmu_vec)`

定义建议：

- 当沿 `μ_u = μ_d = μ_s = μ` 的方向变化时，
  - [x] 对称方向导数应等于三列 Jacobian 按方向组合后的结果

这一 helper 主要用于测试，不一定需要对外导出。

验收：

- [x] 新旧求解器在对称路径上的导数回归通过

### 5.5 Step 4: 决定是否新增 `FixedFlavorMu`

这一项需要先做设计判断，再决定是否实施。

先澄清当前架构语义：

- `FixedMu`、`FixedRho` 这类对象属于约束模式，描述“要求解什么物理约束问题”。
- 当前 flavor-μ 路线并未改变平衡态方程的物理约束，只是把输入从对称 `μ` 参数化扩展为 `μ_u, μ_d, μ_s`，并为后续 susceptibility 提供隐式求导能力。
- 因此，从当前需求出发，flavor-μ 更准确的定位是“参数化扩展 + 求导后端”，而不是新的 `ConstraintMode`。

选项 A：本期不新增 `ConstraintMode`

- [x] flavor-μ 仅作为 susceptibility 路线的内部隐式微分工具
- [x] 优点是改动小、风险低
- [x] 优点是语义上更准确，不把参数化/求导问题误命名成新的求解模式
- [x] 缺点是上层若要统一入口，仍需额外补 facade 或显式参数化选项

选项 B：新增 `FixedFlavorMu <: ConstraintMode`

- [ ] 在 [src/models/solver/Conditions.jl](src/models/solver/Conditions.jl#L178) 附近新增对应条件构造器
- [ ] 在 [src/models/solver/Solver.jl](src/models/solver/Solver.jl) 新增分发入口
- [ ] 仅当后续确认 flavor-μ 需要作为“高层用户可直接切换的标准平衡态入口”时再评估

当前建议：

- [x] 先走选项 A

原因：

- 当前需求来自 susceptibility 实现，不是通用 workflow 需求
- 先打通隐式微分路径更重要，避免一次性扩散到 mode 系统
- 当前实现更像求导模式/可微后端，而不是新的物理约束模式

### 5.6 Step 5: 可选补 facade 层入口

若后续上层模块需要统一平衡态入口，可在 [src/models/pnjl_physics/core/EquilibriumFacade.jl](src/models/pnjl_physics/core/EquilibriumFacade.jl) 增加：

- [ ] `solve_equilibrium_backend(T_fm, mu_vec; ...)`

要求：

- [ ] 与现有标量 `mu_fm` 入口共存
- [ ] 不改变旧入口默认行为

这一项不是阶段 B 的硬前置，但能减少后续 susceptibility 模块对底层 solver 细节的直接耦合。

补充说明：

- 若未来需要“统一入口”，优先推荐把它设计成 facade 的参数化选项，而不是新增 `FixedFlavorMu` mode。
- 更准确的目标语义应是：同一平衡态问题支持 `mu_fm` 与 `mu_vec` 两种输入参数化，并可选择是否返回导数信息。

### 5.7 Step 6: 为 susceptibility 层预留最小输出契约

虽然本清单不直接实现 susceptibility，但建议在导数包装层预留以下稳定输出：

- [x] `x`
- [x] `mu_vec`
- [x] `dx_dT`
- [x] `dx_dmu_vec`

理由：

- susceptibility 层至少需要在固定 `T` 下，对 flavor 化学势方向构造高阶导数
- 若导数接口字段命名反复变化，会把上层实现拖慢
