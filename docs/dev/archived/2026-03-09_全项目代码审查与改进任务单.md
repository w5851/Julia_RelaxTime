### [P0] 配置层：物理常数不一致

#### F-01: 模型配置双轨并存，权威来源不唯一

| 文件 | 值 | 精度 |
|------|-----|------|
| `config/models/njl/*.toml` | 当前实现侧 | 应保留 |
| `config/models/pnjl/*.toml` | 当前实现侧 | 应保留 |
| `config/models/rpnjl/*.toml` | 当前实现侧 | 应保留 |
| `config/njl/*.toml` | 历史遗留 | 应移除 |
| `config/pnjl/*.toml` | 历史遗留 | 应移除 |
| `config/rpnjl/*.toml` | 历史遗留 | 应移除 |

**风险**: 同一 profile 可能因加载路径不同得到不同参数集，代码、测试和文档难以形成单一事实来源。  
**建议**: 删除 `config/njl`、`config/pnjl`、`config/rpnjl`，运行时仅从 `config/models/<model>/` 读取模型参数；`config/physics/` 继续保留为共享物理常数层。

#### F-02: α_em 多源冲突

| 来源 | 值 |
|------|-----|
| `config/njl/default.toml` | 0.0072973525**693** |
| `config/physics/default.toml` | 0.0072973525**664** |
| `src/models/workflows/TransportWorkflow.jl` L164, L203 | `1.0/137.035999084` ≈ 0.00729735**210** |

**风险**: 代码硬编码覆盖配置值，三处值互不一致。  
**建议**: 以 `config/physics/default.toml` 为唯一权威源，代码读取配置而非硬编码。

### [P1] 错误处理不一致

#### F-07: 裸 `catch` 吞异常

`src/relaxtime/RelaxationTime.jl` 约 L402–L407 处存在裸 `catch`，会吞掉所有异常（包括 OOM、中断），属于危险反模式。  
**建议**: 最少应 `catch e; e isa InterruptException && rethrow(); @error ...`。

#### F-08: @warn 策略不统一

| 模式 | 出现位置 | 行为 |
|------|---------|------|
| `@warn ... maxlog=10` + 继续 | TotalPropagator, DifferentialCrossSection | 警告但不停 |
| `throw(DomainError(...))` | 部分运动学检查 | 直接终止 |
| 静默 clamp + 继续 | OneLoopIntegrals, QuarkDistribution | 无日志 |

**建议**: 定义统一的错误处理策略枚举（`:strict`/`:warn`/`:silent`），在运动学阈值等通用校验中集中使用。

### [P1] 性能：全局可变状态

#### F-09: TransportWorkflow 全局缓存线程不安全

```julia
# src/models/workflows/TransportWorkflow.jl L39-42
const _MODEL_CACHE = Dict{Symbol, Any}()
const _PREFER_ENERGY_ANISO_CACHE = Dict{String, Bool}()
const _A_BUILDER_CONFIG_CACHE = Dict{String, NamedTuple}()
```

**问题**:
- `Dict` 可变（`const` 仅阻止重绑定），多线程不安全
- 无大小上限，潜在内存泄漏
- 全局状态使函数行为难以调试与测试

**建议**: 封装为 `WorkflowCache` struct + `ReentrantLock`，通过参数传递：

```julia
mutable struct WorkflowCache
    model_cache::Dict{Symbol, Any}
    energy_aniso_cache::Dict{String, Bool}
    a_builder_config_cache::Dict{String, NamedTuple}
    lock::ReentrantLock
end
```

#### F-10: PolarizationCache 手动尾数位操作脆弱

`src/relaxtime/PolarizationCache.jl` 手动截断浮点尾数 40 位来做缓存键匹配。  
**建议**: 评估用 `round(x; sigdigits=12)` 或 `isapprox(rtol=...)` 替代。

**验收标准**: 全局 `const Dict` 不再直接在模块顶层出现；cache 通过参数注入。

T4-03 评估结论：已新增性能评估脚本 [scripts/perf/relaxtime/evaluate_polarization_cache_quantization.jl](scripts/perf/relaxtime/evaluate_polarization_cache_quantization.jl)。在代表性样本上，`round(sigdigits=12)` 相比当前 mantissa 截断方案表现为：
- 标量量化中位时间约 `140.8 μs` vs `2.605 μs`，慢约 `54x`
- 键构造中位时间约 `397.5 μs` vs `80.2 μs`，慢约 `5x`
- cache-hit 查找中位时间约 `1.601 ms` vs `1.201 ms`，慢约 `1.3x`
- 唯一桶数 `32` vs `64`，分桶更粗，可能改变缓存命中语义

因此当前阶段**不建议**将 `PolarizationCache` 的量化策略替换为 `round(sigdigits=12)`；保留现有 mantissa 截断实现。

T4-04 评估结论：已新增性能分析脚本 [scripts/perf/relaxtime/profile_quark_distribution_hotspot.jl](scripts/perf/relaxtime/profile_quark_distribution_hotspot.jl)，并据此将 `src/QuarkDistribution.jl` 与 `src/models/pnjl_physics/PNJLDistributions.jl` 的 PNJL 分布函数热路径改为代数重标度稳定形式，而不是引入更重的 full log-domain 重构。结果如下：
- 原实现 `quark_distribution(E=0.2, μ=2.0, T=0.005, Φ=0.2, Φbar=0.25)` 会返回 `NaN`
- 改造后 moderate / extreme 样本上新旧“稳定公式”差值均为 `0.0`
- moderate 样本 loop 中位时间从约 `15.6 μs` 降到 `14.0 μs`（quark），从约 `18.25 μs` 降到 `14.3 μs`（antiquark）
- extreme 样本中位时间从约 `509 ns` 降到 `470 ns`（quark）；antiquark 基本持平

因此当前阶段**不建议**做 full log-domain 重写；采用当前代数重标度方案即可同时解决极端参数稳定性与热路径性能问题。

## 六、风险与回退

| 风险 | 影响 | 缓解 |
|------|------|------|
| 参数归一化重构导致数值结果微变 | 回归测试失败 | 先运行完整回归基线，对比重构前后 |
