## 待办（可勾选）

### A. 服务与任务执行模型

- [x] 设计 PNJL 扫描为“长任务 + 结果落盘 + 状态查询”模式，避免阻塞在线接口。
	- [x] 增加作业创建接口（返回 `job_id`），后台执行扫描。
	- [x] 增加作业状态接口（`queued/running/succeeded/failed` + 进度）。
	- [x] 增加作业结果索引接口（返回标准输出路径与元数据）。
- [x] 定义单点求解轻量接口（优先支持小负载快速返回）。
- [x] 明确未来 ξ 扫描的 payload 与作业队列策略。

> 当前实现（2026-02-19）：
> - `POST /api/modules/pnjl-scan/jobs`（创建后台任务）
> - `GET /api/modules/pnjl-scan/jobs/{job_id}`（状态与进度）
> - `GET /api/modules/pnjl-scan/jobs/{job_id}/result`（结果索引与输出文件元数据）
> - ξ payload 策略：`xi` / `xi_values` / `xi_grid(start, stop, step)` 三选一（默认 `xi=0.0`）
> - 队列策略：并发上限 `max_running=2`，排队上限 `max_pending=32`，可选失败重试 `max_retries<=3`
