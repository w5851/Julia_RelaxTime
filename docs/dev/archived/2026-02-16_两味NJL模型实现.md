# 2026-02-16 两味 NJL 模型实现（基于多重派发）

## 1. 目标与范围

### 1.1 目标
- 在现有 `src/models` 新架构基础上，新增**两味 NJL（u,d）**模型实现。
- 通过**多重派发**实现 2f 与 3f 的并存，不破坏现有 3f-NJL/PNJL/rPNJL 行为。
- 公式依据：`docs/reference/formula/models/njl/NJL_core.md` 末尾“**两味NJL模型补充**”（补-1、补-2）。

### 1.2 本次范围（In-Scope）

- `factory` 支持创建 2f 模型。

- 配置文件新增 2f 参数 profile。
- 单测新增：core、factory、omega、implicit differentiation 的 2f smoke + 数值一致性。

### 1.3 非范围（Out-of-Scope）

- 不引入新的 UI/脚本工作流接口。
- 不在本任务内做“两味参数重新拟合”。使用固定参数集（Set-2f-A 默认）。

## 2. 物理公式到代码映射（2f）

来自补充公式：

1) 两味热力学势（补-1）
\[
\Omega_{2f} = -2N_c\sum_{i=u,d}\int \frac{d^3p}{(2\pi)^3}\frac{p^2}{3E_i}[n_i+\bar n_i]
-2N_c\sum_{i=u,d}\int^{\Lambda}\frac{d^3p}{(2\pi)^3}E_i
+2G(\phi_u^2+\phi_d^2)+C
\]

2) 两味质量方程（补-2）
\[
M_i = m_i - 4G\phi_i,\quad i\in\{u,d\}
\]

代码映射约定：
- `calculate_mass_vec(::NJL2Model, φ)`：仅计算 `u,d`，第三分量按兼容策略处理（见第 4 节）。
- `calculate_chiral(::NJL2Model, φ)`：返回 `2G(φ_u^2 + φ_d^2)`。
- `vacuum_contribution(::NJL2Model, masses)`：只对 `u,d` 求和。
- `thermal_contribution(::NJL2Model, masses, Φ, Φbar, mu_vec, T)`：只对 `u,d` 求和，忽略 `Φ/Φbar`。

## 3. 现状与关键约束

当前 3f 假设主要在以下位置：
- `src/models/njl/NJLCore.jl`
	- `NJLParams` 默认 `N_flavor=3`，并含 `K_fm5/m_s0_inv_fm`。
	- `calculate_mass_vec(::NJLParams, ::SVector{3})` 固定三味并含 `K` 混合项。
- `src/models/njl/NJLModel.jl`
	- `vacuum_contribution/thermal_contribution/number_densities` 循环 `1:3`。
- `src/models/state.jl`
	- `MeanFieldState.phi::SVector{3}`（全模型统一状态容器）。
- `src/models/gap_solver.jl`
	- 通用 `solve_gap(::AbstractNJLModel, ...)` 仅支持 `dim=3`。
- `src/models/implicit_gap.jl`
	- `create_implicit_gap_solver(::AbstractNJLModel)` 仅支持 `dim=3`。

结论：
- 需要用“**更具体方法覆盖**”替代“改坏通用契约”。
- 不建议在本次任务中重构 `MeanFieldState` 的三分量约定，优先做最小侵入扩展。

## 4. 多重派发实现方案（推荐）

## 4.1 新增类型与文件

### A. `src/models/njl/NJL2Core.jl`（新增）
定义两味参数与核心公式：
- `module NJL2Core`
- `struct NJL2Params`
	- 必选：`N_color, N_flavor=2, hbarc_MeV_fm, rho0_fm3, Lambda_inv_fm, G_fm2, m_ud0_inv_fm`
	- 不含 `K_fm5`、`m_s0_inv_fm`
- `njl2_params(; profile="default")`
- `calculate_mass_vec(p::NJL2Params, φ::SVector{3})`
	- 只使用 `φ[1], φ[2]`
	- 返回 `SVector{3}`：`(Mu, Md, Ms_stub)`
- `chiral_potential(p::NJL2Params, φ::SVector{3})`
	- `2G*(φu^2 + φd^2)`

### B. `src/models/njl/NJL2Model.jl`（新增）
定义两味模型并实现接口：
- `struct NJL2Model <: AbstractNJLModel`
- `NJL2Model(; profile=get(ENV,"NJL2_PARAM_PROFILE","default"))`
- 覆盖实现：
	- `calculate_mass_vec(::NJL2Model, φ)`
	- `calculate_chiral(::NJL2Model, φ)`
	- `polyakov_potential(::NJL2Model, ...) = 0`
	- `vacuum_contribution(::NJL2Model, masses)`（只累加前两味）
	- `thermal_contribution(::NJL2Model, masses, Φ, Φbar, mu_vec, T; ...)`（只累加前两味）
	- `number_densities(::NJL2Model, ...)`
		- 返回仍保持 `(quark=SVector{3}, antiquark=SVector{3})`
		- 第三分量固定 `0`（兼容已有下游接口）

## 4.2 框架接入

### C. `src/models/Models.jl`
- include 新文件：
	- `include(joinpath(@__DIR__, "njl", "NJL2Model.jl"))`
- export：`NJL2Model`

### D. `src/models/factory.jl`
- `create_model(:NJL2; kwargs...) -> NJL2Model(; kwargs...)`

## 4.3 gap/隐式微分策略

推荐策略：保持主框架最小改动，使用更具体方法覆盖。

### E. `src/models/gap_solver.jl`
新增专用方法：
- `gap_state_dim(::NJL2Model) = 2`
- `gap_initial_guess(::NJL2Model, T, mu_vec) = [φu0, φd0]`
- `gap_residual(::NJL2Model, x, T, mu_vec; kwargs...)`
	- 将 `x=(φu,φd)` 嵌入 `φ=(φu,φd,0)` 后调用 `omega`
	- 返回 `SVector{2}`
- `solve_gap(::NJL2Model, T, mu_vec; ...)`
	- 独立 2 维 NLsolve 流程
	- 返回 `MeanFieldState(phi=(φu,φd,0), Phi=1, PhiBar=1)`

### F. `src/models/implicit_gap.jl`
新增：
- `create_implicit_gap_solver(model::NJL2Model; ...)`
	- `θ=[T,μ] -> x=[φu,φd]`
	- `conditions_impl` 返回二维残差

> 说明：不建议把现有 `AbstractNJLModel` 通用实现直接改成支持 dim=2/3 混合，以免影响已有 3f 行为。优先使用 `NJL2Model` 更具体派发方法。

## 5. 2f 与现有 3f 状态契约兼容规则

由于当前 `MeanFieldState` 固定 `phi::SVector{3}`，两味采用如下兼容策略：

1) 2f 的物理自由度仅 `φu, φd`。
2) `φs` 作为占位分量固定为 `0`。
3) `mu_vec` 仍使用长度 3：默认 `(μ, μ, μ)`；2f 计算中仅使用前两项。
4) 所有 2f 的 flavor-sum 必须明确写 `for flavor in 1:2`，禁止复用 `1:3`。
5) 对外返回 `SVector{3}` 的场景（如 number densities）第三分量为 `0`。

该策略可确保：
- 与 `omega_components/transport_provider` 等现有 API 兼容。
- 不必在本任务中重构通用状态容器。

## 10. 风险与规避

风险 1：误用三味循环导致 2f 混入 `s` 贡献。
- 规避：2f 方法体内显式 `1:2`，并在测试中验证 `μs` 不敏感。

风险 2：`dim=2` 与通用 `AbstractNJLModel` 求解器冲突。
- 规避：提供 `NJL2Model` 更具体 `solve_gap/gap_residual` 方法，不改通用 3f 路径。

风险 3：状态维度兼容问题（`MeanFieldState` 仍是 3 分量）。
- 规避：统一采用 `φ=(φu,φd,0)` 兼容层，避免大范围重构。
