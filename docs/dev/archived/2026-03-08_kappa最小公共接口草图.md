## 1. 设计目标

最小公共接口只解决四件事：

1. 统一 `B/Q/S` 守恒荷量子数的读取
2. 统一从 flavor 净数密度得到 `n_B / n_Q / n_S`
3. 统一构造 `kappa` 的双投影 integrand
4. 为后续 `BQ / BS / QS` 预留同一接口

不在这份草图里解决的内容：

- 最终导出 API 命名
- validation 数据布局
- `lambda` 以外派生 ratio 的输出格式

## 2. 建议先补的 helper

### 2.1 守恒荷标签

建议新增一个内部标签类型或常量约定：

```julia
charge in (:B, :Q, :S)
```

用途：避免后续把 `kappa_BB` 写成三个互相复制的专用函数。

### 2.2 `conserved_charge_value`

建议签名：

```julia
conserved_charge_value(species::Symbol, charge::Symbol)::Float64
```

功能：返回单个 species 对应的无量纲守恒荷量子数。

应满足：

- `conserved_charge_value(:u, :B) == 1/3`
- `conserved_charge_value(:ubar, :B) == -1/3`
- `conserved_charge_value(:u, :Q) == 2/3`
- `conserved_charge_value(:s, :S) == -1`

这是 `kappa` kernel 最基础的权重 helper。

### 2.3 `conserved_charge_densities`

建议签名：

```julia
conserved_charge_densities(rho_vec)::NamedTuple
```

输入约定：

- `rho_vec = (rho_u, rho_d, rho_s)`
- 表示三味净 flavor 数密度

返回建议：

```julia
(B=n_B, Q=n_Q, S=n_S)
```

公式：

$$
n_B = \frac{\rho_u + \rho_d + \rho_s}{3}, \qquad
n_Q = \frac{2\rho_u - \rho_d - \rho_s}{3}, \qquad
n_S = -\rho_s
$$

### 2.4 `enthalpy_density`

建议签名：

```julia
enthalpy_density(pressure::Real, energy::Real)::Float64
```

功能：统一返回

$$
\omega = \epsilon + P
$$

虽然计算很简单，但把它单独包出来能避免以后在 integrand 里散落写 `energy + pressure`。

### 2.5 `kappa_projection`

建议签名：

```julia
kappa_projection(
    species::Symbol,
    charge::Symbol,
    E::Real,
    charge_densities::NamedTuple,
    enthalpy::Real,
)::Float64
```

功能：返回单个投影因子

$$
q_a - \frac{n_q E}{\epsilon + P}
$$

这是从“普通 charge weight”升级到“Landau-Lifshitz 扩散投影”的关键 helper。

## 3. 建议的最小内部 kernel

### 3.1 `kappa_integrand_weight`

建议签名：

```julia
kappa_integrand_weight(
    species::Symbol,
    charge_left::Symbol,
    charge_right::Symbol,
    E::Real,
    charge_densities::NamedTuple,
    enthalpy::Real,
)::Float64
```

功能：返回双投影权重

$$
\left(q_a - \frac{n_q E}{\epsilon + P}\right)
\left(q'_a - \frac{n_{q'} E}{\epsilon + P}\right)
$$

这样做的好处是：

- `BB / QQ / SS` 是同一个 kernel 的对角情形
- `BQ / BS / QS` 只是把左右标签改掉

### 3.2 `diffusion_coefficient`

建议签名：

```julia
diffusion_coefficient(
    req::TransportRequest,
    charge_left::Symbol,
    charge_right::Symbol;
    charge_densities::NamedTuple,
    pressure::Real,
    energy::Real,
    provider=DEFAULT_TRANSPORT_PROVIDER,
    config::Union{Nothing,TransportIntegrationConfig}=nothing,
)::Float64
```

核心职责：

- 复用现有 `_integrate_species_sum`
- 复用现有 mass / mu / tau / distribution 读取
- 新增双投影权重
- 返回某个矩阵元 `kappa_{qq'}`

内部积分骨架目标应接近：

$$
\kappa_{qq'}
=
\sum_{species}
\int dp\,
\frac{p^4}{E^2}
F(p)
\tau
\times
\mathrm{weight}_{qq'}
$$

补充约束：在尚无一手公式或 legacy 对照明确规定 `BQ / BS / QS` 符号之前，单测不应对这些非对角元写死符号预期；当前更稳妥的验收口径是有限性、对称性与矩阵-单元接口一致性。

## 4. 对外第一阶段 API 建议

第一阶段先暴露三个对角元和一个派生量：

```julia
kappa_BB(...)
kappa_QQ(...)
kappa_SS(...)
lambda_from_kappa_BB(kappa_BB, pressure, energy, n_B, T)
```

其中：

- `kappa_BB / QQ / SS` 内部都调用 `diffusion_coefficient`
- `lambda` 不新做动量积分，只复用 `kappa_BB`

建议不要第一版就公开：

```julia
kappa_BQ(...)
kappa_BS(...)
kappa_QS(...)
```

但内部接口必须允许这三个量立即接上。

---

## 5. 建议先补的最小 helper 顺序

按最小可落地顺序，建议先补：

1. `conserved_charge_value`
2. `conserved_charge_densities`
3. `enthalpy_density`
4. `kappa_projection`
5. `kappa_integrand_weight`
6. `diffusion_coefficient`
7. `kappa_BB / kappa_QQ / kappa_SS`
8. `lambda_from_kappa_BB`

这个顺序的好处是：

- 前 5 步都是小 helper，容易单测
- 第 6 步把真正的公共 kernel 固定住
- 第 7、8 步只是薄封装

---

## 6. 最小风险提示

- `kappa_QQ` 是否乘 $4\pi \alpha_{em}$，应作为输出口径选项，而不是硬编码进内部 kernel
- `n_B \to 0` 时 `lambda` 需要单独做保护
- 当前项目已有 `sigma` 的单权重 kernel，但 `kappa` 需要双投影 kernel，不能直接在 `sigma` 上局部补丁式修改

---

## 7. 推荐落点

从当前代码组织看，最自然的落点是：

- helper 放在 [src/relaxtime/TransportCoefficients.jl](src/relaxtime/TransportCoefficients.jl) 的内部工具区
- 若后续 `B/Q/S` 变换在多处复用，再抽到独立公共模块

在正式实现开始前，这份草图足以作为最小接口约束。
