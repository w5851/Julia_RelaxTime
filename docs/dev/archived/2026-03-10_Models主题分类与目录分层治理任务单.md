# Models 主题分类与目录分层治理任务单

更新日期：2026-03-10

> 目标：在继续扩展 `docs/api/models/` 主题前，先固定 `Models` API 文档的信息架构，明确哪些能力属于“流程/合同主题”，哪些属于“模型变体主题”，哪些属于“衍生量主题”，并避免后续继续按一级目录平铺扩张。

---

## 1. 背景与问题定义

截至当前，`Models` 公开表面已经完成以下主题治理：

- `phase`
- `workflows`
- `scans`
- `solver`

这四类主题有一个共同点：它们都可以直接视为 `Models` 统一入口下的主流程、主合同或核心职责主题，因此放在 `docs/api/models/<theme>/` 一级目录下是合理的。

但后续待治理能力已经不再都符合这一条件，至少出现了三类不同语义：

1. **模型家族/模型变体类**
   - 例如 magnetic。
   - 它不是单纯的“一个普通主题”，而是与 NJL、PNJL、RPNJL 等并列的模型变体语义。

2. **衍生量类**
   - 例如 susceptibility、cumulant、各类导数量。
   - 它们更像 `Models` 的派生物理量或响应量族，而不是主流程主题。

3. **跨域高耦合类**
   - 例如 transport provider 及其相关能力。
   - 它同时与 `Models` 导出、`docs/api/relaxtime/` 领域页、workflow 入口产生交叉，不适合在目录方案尚未明确前强行落位。

如果不先做分类治理，后续很容易继续沿用“凡是新主题就直接挂在 `docs/api/models/` 下一层”的旧习惯，导致目录语义混杂、层级失衡，最终又需要二次重构。

## 3. 范围与非目标

### 3.1 范围

- `docs/api/models/` 下后续主题的信息架构规则；
- `ModelsExportIndex.md` 中待治理能力簇的分类重排；
- 后续任务单的落点规范；
- `variants`、`derived` 两类分类层的先行设计。

### 3.2 非目标

- 不在本任务中直接落地 magnetic 正文页面；
- 不在本任务中直接落地 susceptibility/cumulant 正文页面；
- 不在本任务中决定 transport 主题的最终目录和正文结构；
- 不在本任务中改写 `src/models/*` 实现代码；
- 不在本任务中清理所有旧 `docs/api/pnjl/` 或 `docs/api/relaxtime/` 页面。

## 4. 目标分类法

### 4.1 保持一级平铺的主题

继续保留为 `docs/api/models/<theme>/` 一级目录的，仅限以下类型：

- 主流程主题
- 统一入口主题
- 核心合同主题
- 多个上层入口共同依赖的稳定职责主题

当前已落地且符合该条件的主题：

- `phase`
- `workflows`
- `scans`
- `solver`

### 4.2 模型变体主题

此类主题描述的是模型家族、模型变体或模型配置族，不应直接作为 `docs/api/models/` 下的又一个普通一级主题。

首个明确对象：

- magnetic

目录设计原则：

- [x] 不使用 `docs/api/models/magnetic/`
- [x] 应先引入额外分类层，例如 `docs/api/models/variants/...`
- [x] 目录命名要能容纳后续 NJL、PNJL、RPNJL、magnetic 等并列族的继续整理

建议候选路径：

- `docs/api/models/variants/magnetic/`

### 4.3 衍生量主题

此类主题描述的是由模型状态、热力学量或响应函数继续导出的物理量簇，而不是主流程本身。

首批对象：

- susceptibility
- cumulant
- 各类 thermodynamic / flavor / pressure derivatives

目录设计原则：

- [x] 不直接与 `phase/workflows/scans/solver` 并列为新的一级目录
- [x] 应统一放入额外分类层，例如 `docs/api/models/derived/...`
- [x] 同一簇中的不同专题，后续可再拆成子主题，但先共享“derived”总层

建议候选路径：

- `docs/api/models/derived/susceptibility/`
- `docs/api/models/derived/derivatives/`

### 4.4 待定高耦合主题

此类主题跨越多个既有文档体系，若过早固化目录，容易制造新的过渡层。

当前明确对象：

- transport provider / transport-related `Models` exports

当前策略：

- [x] 仅做导出盘点与边界梳理
- [x] 不在目录方案未明确前创建正式主题目录
- [x] 后续单独判断应按 provider、workflow 后处理、还是与 relaxtime 领域页协同组织

## 9. 风险与回退

风险：

- 若 `variants` 或 `derived` 命名后续仍不满意，可能需要在真正创建主题前再做一次轻量重命名。
- 若 transport 后续被证明更适合作为 `relaxtime` 领域页扩展，而非 `Models` 主题，则本任务的“待定策略”必须保持不绑定具体目录。

回退原则：

- 本任务只固定分类法，不创建大量新目录；因此即便后续调整命名，回退成本仍然较低。
