## 1. 目标

- [x] 在不破坏主链可用性的前提下，实现 PNJL/NJL/rPNJL 主能力完全基于 `src/models` 的多重派发架构。
- [x] 将 `src/pnjl` 逐步收敛为“兼容薄层”，最终仅保留必要入口或完全移除。
- [x] 建立可执行的“迁移门禁 + 裁剪门禁 + 回退门禁”，确保每一步都可验证、可回滚。

## 2. 总体策略（四阶段）

### 阶段 A：接口冻结与依赖止血（1~2 天）

- [x] 冻结 models 侧稳定接口（必须通过多重派发分发）：
  - `solve_gap(model::AbstractQCDModel, ...)`
  - `omega(model::AbstractQCDModel, ...)`
  - `omega_components(model::AbstractQCDModel, ...)`
  - `number_densities(model::AbstractQCDModel, ...)`
- [x] 规定新增物理逻辑仅允许进入 `src/models/*`，`src/pnjl/*` 禁止新增公式实现。
- [x] 将 `src/pnjl` 中后端选择逻辑统一收敛到 façade（避免分散 if/else）。

验收：
- [x] 文档与代码入口一致（docs/api + docs/architecture）。
- [x] 现有 smoke 全绿。

### 阶段 B：模型求解链彻底 models 化（3~5 天）

- [x] 完成 `PNJLModel` 在对称/非对称 `mu` 的 models solver 主路径稳定化。
- [x] 将 `src/pnjl/solver/*` 的核心能力迁移为 models 内部求解器实现（保留兼容适配层）。
- [x] 导数链（`ThermoDerivatives`）优先使用 models 入口，不再直接依赖 legacy 内部模块细节。

验收：
- [x] `tests/unit/models/*` 覆盖对称/非对称/多后端路径。
- [x] `UNIT_FILES=models/test_pnjl_solve_gap_backend_switch_smoke.jl;models/test_pnjl_thermo_bridge_multipoint_smoke.jl` 全绿。

### 阶段 C：流程层迁移与 compat 薄层化（4~6 天）

- [x] 将 `src/pnjl/scans/*`、`src/pnjl/workflows/*` 逐步改为“仅编排 + 调 models 接口”。
- [x] 新建或收敛统一流程入口（建议位于 `src/models` 的 workflow/scan 子模块）。
- [x] `src/pnjl/PNJL.jl` 变为兼容 re-export 层（不承载核心计算逻辑）。

验收：
- [x] `tests/unit/pnjl/test_tmu_scan_solver_backend_models_smoke.jl`、`tests/unit/pnjl/test_trho_scan_solver_backend_models_smoke.jl` 全绿。
- [x] workflow（transport/meson）在 `thermo_backend=:models` 无退化。

### 阶段 D：分波次裁剪与下线 `src/pnjl`（3~5 天）

- [x] 按“低风险→中风险→高风险”分三波删除/下线：
  - [x] Wave-1：已被 façade 完全替代的重复桥接模块。
  - Wave-2：已无直接调用的 legacy core 计算模块。
  - Wave-3：兼容入口（确认外部脚本/服务无依赖后再移除）。
- [x] 每波执行“删除前快照 + 删除后 smoke + 失败秒回滚”。

验收：
- [x] `grep` 与依赖图确认无残留调用。
- [x] smoke 与关键定向测试全绿。
