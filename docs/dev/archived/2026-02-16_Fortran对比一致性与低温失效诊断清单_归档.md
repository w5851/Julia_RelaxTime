- B2.2（continuation 依赖）证据：

  - 结论：对起始点与 continuation 路径高度敏感，属于算法路径依赖问题。
- B2.3（求解器参数敏感性）证据：
  - 在可解路径（`rho=0.05~0.07`）分别取 `maxits=20/60/200`：

  - 三组输出逐列一致（在导出精度内无可见差异）。

## 高温可解点一致性专项复核（2026-02-14）

### 目标

### 复核口径

- 对比汇总：`outputs/results/highT_match/fortran_julia_compare_summary_highT.csv`

### 结果结论

- 结论 1：**高温可解点主字段仍不匹配**。
  - 主字段 `phi_*/Phi/PhiBar/mu_*/mu_B/pressure` 在有效样本上 `pass_ratio=0`。
  - 仅密度字段 `rho_u/rho_d/rho_s` 在有效样本上高通过（`pass_ratio=0.8`，1 点因 Julia 不收敛 missing）。
- 结论 2：当前“匹配失败”更像**参数口径差异**，而非单纯求解器容差问题。

### 原因分析（证据链）

1. **模型基参数未对齐（高优先级）**
  - Fortran `main.f90` 使用：`Lambda=637.720, G_Lam2=2.914, K_Lam5=75.968, m0_s=183.468`。
  - Julia `pnjl_constants` 默认来自 `config/pnjl/default.toml`：`Lambda=602.3, G/Lambda^2=1.835, K/Lambda^5=12.36, m_s0=140.7`。
  - 这会系统性改变 `phi`、有效质量与化学势解。

2. **Polyakov/Vandermonde 口径未对齐（高优先级）**
  - Fortran 主程序中 `ku=0.0`；
  - Julia rPNJL 配置当前为 `kappa=0.1`（`config/models/rpnjl/default.toml`）。
  - 该差异直接影响 `Phi/PhiBar` 与热势，进而影响 `mu` 与压强。

3. **约束一致但共轭变量不一致（现象层）**
  - 由于双方都在解固定非对称密度约束，`rho_*` 可高度一致；
  - 但参数不同导致达到同一密度时对应的 `mu`、`phi`、`pressure` 不同。

### 下一步建议（最小验证）

- 做一个“**参数口径对齐试验**”再重跑上述 5 点：
  1) 在 Julia 新建 Fortran 对齐 profile（NJL 基参数 + rPNJL 的 `kappa=0`、`b4=7.555`）；
  2) 固定现有求解器设置，重算 `highT_match`；
  3) 若主字段显著改善，则可确认主因是“参数口径差异”；
  4) 若仍不改善，再进入公式级差异排查。

  ### 同参数+同初值单点对齐实验（2026-02-14）

  - 目的：将差异拆分为“分支差异”与“公式/约束实现差异”。
  - 脚本：`scripts/debug/analyze_single_point_alignment.jl`
  - 点位：`(T, rho/ρ0)=(100,0.5)` 与 `(150,0.8)`。

  - 产物：

    - `outputs/results/highT_match/single_point_alignment_T150_R0p8.csv`

  - 关键证据：
    1. **Fortran 状态代入 Julia 残差并不小**

      - 说明分支选择问题真实存在，且与物理性判据耦合。

  - 结论：
    - 当前差异是“**公式/约束实现差异 + 分支差异**”的混合问题；

  - `(T=2.0, rho=0.16)`：`final_converged=true`，`final_residual≈9.83e-10`
  - `(T=2.0, rho=0.02)`：`final_converged=true`，`final_residual≈9.63e-10`
  - 两个残余失败点均被成功救回。

- 影响评估：
  1. 先前“刚性失败点”可通过分量加权路径穿越，说明根盆地可达但直接等权求解路径不稳；
  2. 该原型为后续主链路工程化提供了可行技术路线（优先作为失败点 fallback，而非替换全局默认）。

- 下一步建议：
  1. 将该策略封装为 `WeightedBlockFallbackSeed`（或等价 solver fallback）；
  2. 仅在 `hybrid` 失败点触发，控制计算开销；
  3. 在 `T=2,3` 全网格回归评估“成功率增益 vs 额外耗时”。

### 低温难解机理分析（2026-02-15）

用户关切：是否可能由巨热力学势积分项（固定大区间积分，低温被积函数局域化）导致低温求解困难。

- 实现核查：
  - 当前热积分采用固定动量区间 `p ∈ [0, 10]` 的 Gauss-Legendre（`src/pnjl/core/Integrals.jl`）；
  - 对数项采用 LSE/保护（`calculate_log_term`），可抑制低温指数溢出；
  - 低温下确实存在“被积函数窄峰/陡峭”风险，理论上可能要求更高积分分辨率。

- 实证（积分分辨率灵敏度）：
  - 脚本：`scripts/debug/benchmark_trho_integration_sensitivity_T1_T4.jl`
  - 汇总：`outputs/results/_tmp_trho_integration_sensitivity_T1_T4_summary.csv`

- 关键结果：
  - `T=1`（`iterations=400`）
    - `(p_num,t_num)=(24,8)`: `0/20`
    - `(48,8)`: `0/20`
    - `(24,16)`: `0/20`
    - `(48,16)`: `0/20`
    - 仅耗时显著上升（约 `154s -> 459s`），覆盖无改善。
  - `T=4`
    - 全部配置均 `20/20` 成功，仅耗时变化。

- 结论（当前证据下）：
  1. 低温失败“可能含有积分难点”，但**不是主导瓶颈**；
  2. 至少在当前实现中，单纯提高积分节点并不能改善 `T=1` 覆盖；
  3. 主导因素更像是“约束耦合 + 分支盆地可达性”（与此前 `f6/f7` 主导残差、seed 路径敏感性结论一致）。

- 下一步建议（若继续攻 `T=1`）：
  1. 在失败点触发“分块约束求解 + 选择性高迭代预算”（而非全局加密积分）；
  2. 额外增加“自适应动量窗局部加密”实验，仅用于机理确认，不直接作为主线默认。
