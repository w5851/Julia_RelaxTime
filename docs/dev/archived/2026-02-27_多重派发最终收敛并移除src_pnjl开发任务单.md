# 多重派发最终收敛并移除 `src/pnjl` 开发任务单

更新日期：2026-02-27

> 目标：在保持主线可用、门禁稳定、可回退的前提下，将当前仍依赖 `src/pnjl` 的能力迁移到 `src/models`，并最终固化为“无 `src/pnjl` 目录结构”。

---

## 1. 背景与核心目标

- [x] 核心目标 A：运行时主入口不再依赖 `src/pnjl/PNJL.jl`，统一由 `src/models` 承载。
- [x] 核心目标 B：删除 `src/pnjl/**` 后，`UNIT_PROFILE=smoke` 与关键回归门禁持续通过。
- [ ] 核心目标 C：形成“提交级”无 `src/pnjl` 状态，避免被回退演练恢复。

---

## 2. 范围与非范围

### 2.1 本阶段范围（In Scope）

- [x] 清理 `src/models/**` 中对 `src/pnjl/PNJL.jl` 的直接路径依赖。
- [x] 将 `workflow/scan/derivative` 所需 legacy 能力迁移为 models 原生实现或 models 侧稳定适配层。
- [x] 移除 `src/pnjl/**` 并同步门禁脚本、CI、文档、台账模板路径与口径。
- [ ] 完成删除前后双轮回归、回退演练（commit 级回退而非目录 restore）与证据归档。

### 2.2 非范围（Out of Scope）

- [ ] 不引入新的物理模型功能。
- [ ] 不扩展与本迁移无关的服务端/UI 功能。
- [ ] 不在本期重做已稳定的数值算法（除非为移除 `src/pnjl` 的必要改造）。

---

## 3. 现状盘点（起点）

- [x] 已存在 models 统一入口与迁移门禁（含 data 输出路径门禁与 CI 独立工作流）。
- [x] 数据输出路径已统一收敛到 `data/outputs/...`。
- [x] `src/models` 多处仍直接指向 `src/pnjl/PNJL.jl`（删除将导致入口断裂）。
- [ ] `src/pnjl/**` 仍为 HEAD 跟踪内容，尚未形成提交级“无目录”状态。
