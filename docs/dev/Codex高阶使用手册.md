# Codex 协作手册

项目约束以 [AGENTS.md](../../AGENTS.md) 为准；本页只说明如何选择计划、文档与 skill，不再复制编码规则或已落地的 skill 设计。

## 计划与项目记录

明确的小任务直接实施、验证并汇报。复杂或模糊需求可使用 Codex 计划模式梳理目标、依赖和验收条件；不因此自动生成仓库任务单。

信息按用途保存：

| 信息 | 位置 |
| --- | --- |
| 本次工作的步骤与即时进度 | 对话计划或已有 issue/PR |
| 跨主线关系、阻塞和恢复入口 | `config/governance/task_tracks.toml` 中相关条目 |
| 需要共享的设计、稳定契约与决策 | 现有 `docs/architecture/`、`docs/api/`、`docs/guides/`、`docs/decisions/` |
| 数值结果、验收、作者决策和来源 | 相应分析/产物记录及其证据链接 |

详细规则和现有 ledger 的文件要求见[任务跟踪治理](task_tracking_governance.md)。按用户指定的文档继续时，直接核对它的当前范围、未完成项和验收证据，无需经过额外的“设计任务单 → 按文档实现”技能链。

## skill 保留标准

skill 应提供模型从通用知识中无法可靠获得的信息，或可直接复用的工具：

- 项目特有的公式约定、入口、配置和数据契约；
- 数值回归、正式晋升、图件来源等具体工作流；
- 归档等有现成脚本、需要维护兼容性的操作。

通用 Julia 语法、多重派发介绍、泛化的“先计划、再测试”步骤，以及重复 `AGENTS.md` 的清单，不作为 skill 的主要内容。普通 Julia 实现不以调用语言基础 skill 为前置条件；本仓库的 include 加载方式、`Main` 共享类型和稳定入口约束仍由[模块规范](Julia模块引用规范准则.md)维护。

[仓库 skills](../../.agents/skills/)只承载各自必要的差异。跨主线续接需要 `codex-task-harness` 时，只恢复选定条目及其依赖；明确任务直接执行。归档和科学工作流按实际需求选择；显式要求的日志直接按目标文件格式补充，不串联全部 skill。

## 控制恢复上下文

先读当前目标、剩余工作和直接证据，遇到具体问题再查历史。未冻结的当前摘要随事实更新；原始实验与作者决策保留在证据记录中，不反复粘贴进任务单或台账。

skill 的名称与描述参与发现，完整正文只在选用时加载。减少磁盘上的文档数量并不等于减少当前上下文；更有效的是收窄触发条件、减少重复规则，并避免默认全读历史正文。
