# 开发前的聚焦检查

先明确要实现的行为、已有权威入口及完成信号。以下问题按任务相关性选择；常规小改动不需要写完整设计文档。

## 科学与数值实现

- 公式、近似、符号、单位和参数来源是否明确？
- 入口是否通过当前 `Models`/稳定 CLI，已有调用方是否受影响？
- 分支选择、失败点、非有限值和求解状态如何表达？
- 本次变化需要什么已有测试、固定点或误差证据？
- 数值承诺变化是否有理由，baseline 是否需要更新？

## 稳定工作流和服务

- 参数优先级、有效配置、输出字段和错误行为是否与说明一致？
- 断点续算、重跑与覆盖行为是否保护已有结果？
- 只有涉及 HTTP/UI/并发时才检查对应权限、状态、输入和竞态边界。

## 实现与维护

- 将通用逻辑放在 `src/`，一次性分析与性能探针放在对应 `scripts/` 子目录。
- 复用现有覆盖；新测试能说明其捕获的真实错误。
- 对复杂算法解释原因与假设，稳定入口变化同步 API/脚本说明。
- 优化前确认瓶颈，避免为普通修复展开额外重构。
- 聚焦验证通过后交付；只有具体剩余风险才扩大范围。
