### 5.1 `hbarc` 精度不一致

| 配置文件 | 值 | 备注 |
|---------|-----|------|
| `config/njl/default.toml` | `197.3269804` | 高精度 |
| `config/pnjl/default.toml` | `197.327` | 低精度，相对差异 ~1.5×10⁻⁵ |

- [x] **P2.1** 统一 `hbarc` 精度为 PDG 标准值 `197.3269804`
- [x] **P2.2** 评估当前是否因此导致 NJL/PNJL 跨模型对比时的数值偏差
  - 评估方法：在相同 MeV 物理点下，分别用 `hbarc=197.327` 与 `hbarc=197.3269804` 运行 NJL/PNJL（FixedMu，`p_num=8,t_num=4`），比较跨模型差值 `Δ = p_PNJL - p_NJL` 的漂移。
  - 结果：
    - 点 `(T,μ)=(110,20) MeV`：`|Δ_new-Δ_old|=2.506e-8`，相对漂移 `3.975e-7`
    - 点 `(T,μ)=(130,40) MeV`：`|Δ_new-Δ_old|=7.593e-8`，相对漂移 `3.974e-7`
  - 结论：`hbarc` 精度统一对 NJL/PNJL 跨模型对比影响可忽略（~`4e-7` 量级）。
  - 同步修复：`config/physics/default.toml` 仍残留旧值，已对齐为 `197.3269804`，避免默认运行路径继续使用旧常量。

- [x] **P2.5** 评估根级文件内收方案（需考虑对 relaxtime 全链路的影响）

### 10.2 目标测试分类定义

| 类型 | 原则 | 运行场景 | 存放位置 |

| 类型 | 处置 |

| 性能探针（profiling） | 迁至 `scripts/perf/`，使用 `perf` / `Profile.jl` 做瓶颈诊断 |

### 10.5 CI/CD 分层配置

#### 10.5.1 层级定义

| 层级 | 触发条件 | 覆盖范围 | 时间预算 |
|------|---------|---------|---------|
| **unit-smoke** | 每次 push / PR | `tests/unit/` 中 SMOKE_FILES 精选子集 | < 2 min |
| **unit-full** | PR merge / nightly | `tests/unit/` 全量 | < 10 min |
| **integration** | PR merge / nightly | `tests/integration/` 全量 | < 15 min |
| **validation-smoke** | PR merge | `tests/validation/` 中精选基线点 | < 5 min |
| **validation-nightly** | nightly | `tests/validation/` 全量（含大网格基线） | < 30 min |
| **benchmark** | 手动 / 周期 | `benchmark/` 使用 PkgBenchmark | 不限 |

#### 10.5.2 runtests.jl 分层入口设计

```julia
# tests/unit/runtests.jl — 保留现有 UNIT_PROFILE=smoke|full 机制
# tests/integration/runtests.jl — 新增
# tests/validation/runtests.jl — 新增

# 顶级入口 (CI 调用)
# ENV["TEST_SUITE"] = "unit" | "integration" | "validation" | "all"
```

#### 10.5.3 为什么将 benchmark 独立于 tests/

1. **关注点分离**：正确性测试（`tests/`）验证"对不对"；基准测试（`benchmark/`）监测"快不快"。混合管理会导致 CI 配置复杂度上升和误判（性能波动触发正确性门禁失败）。
2. **依赖隔离**：`BenchmarkTools.jl` 是重量级依赖（含统计分析、自适应采样），不应出现在正确性测试路径的启动时间中。独立 `benchmark/Project.toml` 可按需追加 `BenchmarkTools`、`PkgBenchmark` 而不污染主项目 `[deps]`。
3. **结果可比性**：`BenchmarkTools.@benchmark` 产出的 `BenchmarkGroup` / `Trial` 对象可序列化比较（`judge(new, old)`），适合做 PR 间的性能回归检测。`tests/perf/` 下的 `@elapsed` / `println(timing)` 无法做到这一点。
4. **Julia 生态惯例**：`PkgBenchmark.jl` 默认寻找 `benchmark/benchmarks.jl` 入口，独立顶级目录符合生态约定。

#### 10.5.4 perf 工具定位

`perf`（此处指 `Profile.jl` / `@profile` / flamegraph）用于**诊断**性能瓶颈，是开发者工具而非 CI 工具：

- 放在 `scripts/perf/`，手动执行。
- 产出物（flamegraph SVG / allocation report）放在 `data/outputs/perf/`（已有目录）。
- 不纳入 CI 流水线。
