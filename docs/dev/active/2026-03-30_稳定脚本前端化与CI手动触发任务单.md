# 稳定脚本前端化与 CI 手动触发任务单

## 1. 目标

- 将“已稳定、可复现”的核心脚本能力固化为前端可操作入口，减少人工命令依赖。
- 将同一批能力固化为 CI `workflow_dispatch` 手动触发入口，形成可审计执行路径。
- 保持 localhost 默认链路可用，不引入破坏性接口变更。

## 2. 范围与非范围

### 2.1 本期范围（MVP）

- [x] 固化 1-2 条高频稳定脚本为前端任务中心入口。
- [ ] 固化同一能力到 GitHub Actions 手动触发工作流（`workflow_dispatch`）。
- [ ] 前端与 CI 共用同一参数契约（字段名、默认值、错误码口径一致）。
- [x] 产物路径与执行摘要可回填到文档/PR（便于审计）。

### 2.2 非范围（本期不做）

- [ ] 不做远程集群调度、队列扩容、自动弹性伸缩。
- [ ] 不做全量脚本一次性迁移（先做最小可用闭环）。
- [ ] 不引入新的前端框架重构（沿用现有 `web/js` 结构）。

## 8. 风险与回退

- [ ] R1 参数口径漂移风险：以 `docs/api/data_contracts.md` 为单一基线，变更先更文档再改实现。
- [ ] R2 CI 输入过多导致误触发：首版仅开放最小必要参数，其余走默认模板。
- [ ] R3 前端与 CI 重复维护风险：优先抽取共享参数构造/校验逻辑，避免双份散落实现。
- [ ] R4 过早删除旧脚本可能破坏历史复现；先标记弃用并保留兼容周期。
- [ ] R5 如出现回归，回退策略为“保留现有 API 与脚本路径”，前端入口降级为只读提示。
