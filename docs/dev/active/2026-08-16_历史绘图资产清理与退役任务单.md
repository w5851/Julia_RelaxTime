## 1. 目标

在不改变数值语义、不覆盖正式产物、不删除历史证据的前提下，建立 PNG/PDF/SVG 资产 registry 和清理候选报告，为后续逐项退役提供可审计输入。

本任务的术语是 `asset inventory + dry-run + allowlist cleanup`。历史资产真正退出正式工作树时，另称为 `figure asset retirement`，不得与本 PR A 混在一起。

## 2. PR A 范围

- 扫描 `data/outputs/figures` 中 Git 已跟踪的 PNG、PDF、SVG。
- 记录文件 hash、大小、格式元数据、manifest 关联、provenance sidecar 和 Git tracked 状态。
- 按 case/variant 聚合资产，生成 `asset_registry.json` 和 `cleanup_candidates.csv`。
- 将历史/未注册 manifest、多个 variant、外部引用未知项标为 `owner_review_only`。
- 记录当前未跟踪资产被排除且不修改的规则。

## 3. 非范围

- 不删除、移动、重命名或覆盖任何 PNG/PDF/SVG。
- 不扫描或处理当前未跟踪的 C1/C2/pilot 资产，不把它们纳入可删除候选。
- 不修改 CSV/JSON 数值输入、solver、Maxwell、C2、reference、transport 或绘图数值语义。
- 不根据文件名、时间、格式或单纯 byte hash 自动判定历史资产可以删除。
- 不把 `docs/analysis` 诊断证据自动迁移到正式图目录。

## 4. 分类和动作语义

| 分类 | PR A 动作 | 后续默认策略 |
| --- | --- | --- |
| `contract_case` | 记录 | 保留，除非作者确认存在冗余 variant |
| `legacy_manifest` | `owner_review_only` | 默认保留为 `legacy` |
| `legacy_unregistered` | `owner_review_only` | 先确认论文/报告引用，再决定是否归档 |
| `invalid_manifest` | `owner_review_only` | 先修复或保留证据，不直接删除 |
| `diagnostic` | 不进入本 registry | 继续保留在 `docs/analysis` |
| `pilot_review` | 不进入 tracked-only registry | 保留当前工作树，等待作者另行决定 |

PR A 的 `proposed_action` 不允许取 `delete` 或 `move`。任何实际退役必须在后续 PR 中提供路径、SHA-256、理由、替代路径和作者批准。

## 5. 作者人工审核 gate

作者只需审核 registry 的 `review_groups`，不需要逐个打开全部图像。每个审核组需要回答：

1. 是否仍被当前论文、supplement、报告或外部幻灯片引用；
2. 多个 case/variant 中哪个是 canonical；
3. 历史版本是继续原地保留、进入可恢复 quarantine，还是列入后续删除候选。

仓库外引用无法由脚本可靠判断，因此没有作者确认的资产默认继续保留。

## 6. 后续 PR B 入口

只有作者完成人工审核后，才创建 PR B。PR B 必须：

- 使用作者批准的精确 allowlist；
- 在执行前再次校验路径和 SHA-256；
- 优先使用可恢复归档，不直接 `Remove-Item`；
- 记录 relocation/deletion manifest；
- 检查仓库引用、manifest 输出和文档链接没有断裂；
- 不处理未经明确批准的 C1/C2/pilot 或正式历史证据。

## 9. PR B 执行建议和人工介入点

PR B 进入实际文件操作前，先生成一次新的 preflight manifest。该 manifest 只允许来自作者审核记录的精确路径，并逐项记录：绝对路径解析结果、Git tracked 状态、当前 SHA-256、计划动作、理由、替代路径或目标路径。若路径不存在、状态不是预期值、SHA-256 与 registry 快照不一致，或命中未跟踪 C1/C2/pilot 资产，应停止执行并重新审核；不得用宽泛 glob 补偿。

执行顺序建议如下：

1. 对保留项只做分类和必要的 `legacy` 说明，不重绘、不覆盖、不修改数值文件。
2. 对 analysis 迁移项用显式路径移动图像证据，保留结果 CSV 和 provenance，并在目标目录补 README；迁移后记录源/目标清单与 hash。
3. 对删除项只按 allowlist 处理，先记录删除前 hash 和仓库引用，再提交精确删除；不直接使用未验证的递归删除命令。
4. 对 coarse transport case 使用显式 `git mv` 完成 `xi005` 改名，只更新路径型元数据和引用，不改 CSV 内容或 transport 数值语义。
5. 执行后重新扫描引用、manifest、文件 hash 和 Git diff，确认 solver、Maxwell、C2、reference、transport 数值文件及未跟踪 pilot 均未被改动。

PR B 尚需作者介入的内容只有一次性操作性审核：查看执行前 preflight manifest 是否仍与本记录的 allowlist 和 hash 一致，以及查看 analysis 迁移后新增的 README 是否准确。无需重新逐个审核已经确认保留的 legacy PNG。若发现新的论文/补充材料/报告外部引用，PR B 应暂停并回到对应 review group，而不是自行改变动作。
