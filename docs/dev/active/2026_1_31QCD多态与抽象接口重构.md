## Plan: 多态抽象接口重构

TL;DR — 将现有 PNJL 实现封装为 `AbstractQCDModel` 子类，提取共享基类到 `src/models/base`，新增 `src/models/pnjl` 与 `src/models/rpnjl` 子模块，并通过 `models/factory` 与兼容 shim 平滑迁移，减少一次性破坏并方便未来扩展（详见步骤）。

### Steps
1. 定义接口：在 `src/models/interface.jl` 中添加 `abstract type AbstractQCDModel end` 与必需方法（如 `calculate_effective_mass`, `calculate_polyakov_loop`, `thermodynamic_potential`, `solve`）。  
2. 提取基础工具：把常量与通用积分/热力学函数移到 `src/models/base/Constants.jl`、`src/models/base/Integrals.jl`、`src/models/base/Thermodynamics.jl`。  
3. 封装 PNJL：实现 `src/models/pnjl/PNJLModel.jl`，使 `PNJLModel <: AbstractQCDModel`，内部复用现有 pnjl 代码。  
4. 添加兼容层：写 `src/models/compat/PNJL_compat.jl`，保留旧导出接口并委托到新模型（逐步移除旧路径）。  
5. 通用扫描器：重构 `scripts/*` 与 `src/scans/`，通过 `src/models/factory.jl` 由配置创建模型实例并运行扫描。  
6. 更新测试：按模块逐步迁移 `tests/unit/pnjl/*` -> 使用 `PNJLModel` 并运行回归测试。

### Further Considerations
1. 兼容策略：先用 `compat` shim / wrapper（低风险）再逐步删除旧导出。  
2. 数值风险：重点验证 `ImplicitSolver` 与导数（`mass_derivatives`）的一致性。  
3. 实施顺序：先完成接口 + PNJL 封装，再实现 rPNJL 与扫描改造（Option A: 并行；Option B: 顺序）。
