# API 契约与任务中心推进任务单（承接 03-29 主任务单）

## 1. 目标

- 承接主任务单中未完成的阶段 A/B/D，形成可执行的下一阶段交付批次。
- 在不回退现有 localhost 闭环的前提下，推进“契约稳定化 + 任务中心应用化”。

- 主任务单：`docs/dev/active/2026-03-29_前后端分离中长期目标与前端短期待开发任务单.md`

## 3. 范围与批次

### Batch-1：阶段 A+B（契约层与 API 产品化）

- [ ] A1 将 `run_*.jl` 核心能力下沉到 `Models` / `src/models/entrypoints.jl`。
- [ ] A2 保留脚本作为 CLI 编排壳，避免前端依赖脚本参数细节。
- [ ] A3 统一同步/异步入口参数命名与默认值。
- [ ] B1 输出稳定 API 契约（版本、参数 schema、响应 schema、错误码）。
- [ ] B2 明确同步短任务与异步扫描任务的边界。
- [ ] B3 补齐最小契约示例（最小请求、错误请求、成功响应）。

### Batch-2：阶段 D（任务中心应用化）

- [ ] D1 从演示页升级为任务中心：提交、轮询、查看、重试。
- [ ] D2 增加参数配置、结果浏览与导出入口。
- [ ] D3 引入路由与状态管理，降低页面耦合。
- [ ] D4 保持现有 API 适配层兼容，不破坏 localhost 默认链路。

### Batch-3：DoD 与 P1 尾项收口

- [ ] G1 前端仅依赖 HTTP API，不直接调用 `run_*.jl`。
- [ ] G2 API 文档、错误码、示例请求可复现。
- [ ] G3 至少 1 条端到端链路稳定运行（创建任务 -> 轮询状态 -> 获取结果 -> 下载/导出）。
- [ ] G4 异常路径（参数错误、队列满、任务失败、超时）均有可理解提示。
- [ ] P1-1 常用参数模板（快捷填充）。
- [ ] P1-2 历史任务列表（按 `job_id` 回看）。
- [ ] P1-3 结果可视化（基础折线/热图）。

## 4. 验证与证据

## 5. 里程碑建议

- [ ] M1（短期）：完成 Batch-1，形成稳定 API 契约基线。
- [ ] M2（中期）：完成 Batch-2，任务中心达到可用形态。
- [ ] M3（收口）：完成 Batch-3，主任务单转为里程碑跟踪文档。

## 6. 风险与策略

- [ ] R1 若 A/B 涉及较大接口变更，先提供兼容层，避免前端主流程中断。
