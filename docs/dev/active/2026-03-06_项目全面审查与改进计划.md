# 项目全面审查与改进计划

更新日期：2026-03-06

> 目的：基于对整个 Julia_RelaxTime 项目的全面审查，系统梳理当前架构迁移完成度、遗留问题、测试覆盖缺口，并给出可执行的分阶段改进计划。

---

## 一、整体审查结论

### 1.1 项目现状概述

项目已完成从旧架构到基于多重派发的新架构 (`src/models/`) 的**主体迁移**，核心物理模型（NJL/NJL2/PNJL/rPNJL/PNJLMagnetic）均已在新架构下实现，旧架构目录 `src/legacy_pnjl/` 和 `src/models/pnjl/`（旧版）已物理删除。但迁移尚存"最后一公里"问题——多个兼容层、Facade 桥接、deprecated 参数仍活跃于代码中。

### 1.2 架构迁移完成度评估（按模块）

| 模块 | 完成度 | 评估说明 |
|------|--------|----------|
| **类型层次** (`abstract_model.jl`) | ✅ 100% | 类型树完备，接口契约清晰 |
| **NJLModel / NJL2Model** | ✅ 100% | 完全原生实现，无 legacy 依赖 |
| **PNJLModel** | 🔶 90% | 物理实现完整，但 `solve_gap` 仍保留 deprecated 的 `solver_backend`/`fallback_legacy_on_failure` 参数 |
| **RPNJLModel** | 🔶 70% | 明确标记为"MVP shell"，`number_densities` 直接委托给 PNJLModel，thermal/vacuum 复用 PNJL |
| **PNJLMagneticModel** | 🔶 80% | 标记为"minimum viable version"，大部分委托给 PNJLModel |

| **scans/** | ✅ 95% | TmuScan/TrhoScan/DualBranch 完全原生 |
| **phase/** | ✅ 90% | PhaseCore/CEPDetector/CrossoverLine/PhasePipeline 功能完备，N1/N2 批次已完成 |
| **workflows/** | 🔶 85% | WorkflowParamAdapters 仍有 NamedTuple depwarn |

## 五、关于回归测试 vs 验证测试的策略

### 5.1 定义区分

| 类型 | 回归测试 (Regression) | 验证测试 (Validation) |
|------|----------------------|----------------------|
| **目的** | 确保代码变更不改变输出 | 确保输出物理正确 |
| **参考源** | 自身历史版本（baseline CSV） | 外部参考（Fortran/Mathematica/文献） |
| **容差** | 严格（`rtol=1e-6` 量级） | 可适度宽松 |
| **前置条件** | 无（运行当前代码生成 baseline） | 需要外部参考数据 |
| **何时运行** | 每次提交 / nightly | 里程碑节点 |

### 5.2 建议执行序

1. **先做回归测试**（阶段 0）：不需要外部数据，可立即执行。生成的 baseline 本身就是当前代码数值行为的"快照"，为后续重构提供安全网。
2. **再做验证测试**（阶段 3）：等待用户获取 Fortran/Mathematica 参考数据后启动。验证测试可以复用回归测试的固定点选取和测试框架。

### 5.3 回归测试固定点选取原则

- **物理覆盖**：hadron 相 (低 T, 低 μ)、quark 相 (高 T)、crossover 区域、一阶相变附近、CEP 附近
- **参数覆盖**：xi=0（各向同性）和 xi≠0（各向异性）
- **模型覆盖**：每个模型类型至少 5 个点
- **可复现**：使用 TOML 配置文件中的 unittest/default 参数集
- **容差标注**：每个 `isapprox` 都显式标注 `rtol` 和 `atol`，避免隐式默认
