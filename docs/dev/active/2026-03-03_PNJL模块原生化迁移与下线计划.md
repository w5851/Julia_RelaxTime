# PNJL 模块原生化迁移与下线计划

更新日期：2026-03-03

---

## 1. 背景与目标

### 1.1 背景

项目当前存在两套并行的 PNJL 实现入口：

| 层级 | 入口 | 特征 |
|------|------|------|
| **旧架构** | `src/models/pnjl/PNJL.jl` (module PNJL) | 单体模块，IncludeOnce 引导，`if !isdefined(Main, :PNJL) … end` 包裹 |
| **新架构** | `src/models/Models.jl` (module Models) | 多重派发，AbstractQCDModel 层次，多模型统一接口 |

两者呈**共生关系**：Models 直接 `include` 了 `PNJLCore.jl`、`PNJLDistributions.jl`、`PNJLModel.jl`、`PNJLMagneticModel.jl` 等核心物理文件，但 solver、scan、derivative 等高层流程模块仍由 PNJL 独占，Models 只通过 `entrypoints.jl` / `derivative_entrypoints.jl` 以 `invokelatest` 转发到 PNJL。

### 1.2 目标

1. 将 `src/models/pnjl/` 中 **尚未原生化的功能**（solver、derivatives、scan 桥接、facade）迁入 `src/models/` 下，采用多重派发原生设计。
2. 将所有外部引用（workflow、script、test）从 `PNJL.X` 改为 `Models.X`。
3. **删除 `src/models/pnjl/` 整个目录**，完成旧架构退役。

### 1.3 非目标

- 不改变 `Constants_PNJL`（`src/Constants_PNJL.jl`）模块的命名与位置——它是独立常量表，不属于 PNJL 求解器。
- 不改变 `PNJLQuarkDistributions`（`src/QuarkDistribution.jl`）的命名——它是独立分布模块。
- 不在本轮引入新物理功能或修改数值结果。
- 不重写 NJL/NJL2/RPNJL 模型的实现（虽然它们将受益于统一的 solver 接口）。

### Phase 1: Solver 原生化（核心迁移）

> 目标：将 SeedStrategies / Conditions / ImplicitSolver 迁入 `src/models/solver/`，使 Models 拥有完整自主求解能力。

- [ ] **P1.1** 迁移 `SeedStrategies.jl`（823 LOC）→ `src/models/solver/SeedStrategies.jl`
  - 保持模块名 `SeedStrategies`
  - 删除对 PNJL 模块作用域的隐式依赖（如 `PNJLCore`、`Thermodynamics`），改为显式 `import Models: …` 或参数传入
  - 导出所有 seed 常量（`HADRON_SEED_5` 等）到 Models 顶层
  - 验收：`using Models: HADRON_SEED_5, MultiSeed, PhaseAwareSeed` 可用
- [ ] **P1.2** 迁移 `Conditions.jl`（362 LOC）→ `src/models/solver/Conditions.jl`

- [ ] **P1.3** 迁移 `ImplicitSolver.jl`（1041 LOC）→ `src/models/solver/ImplicitSolver.jl`

  - Newton→TrustRegion 双降级、auto-MultiSeed、物理性检查原样保留

  - 验收：`Models.solve(model, FixedMu(), T, μ)` 返回 `SolverResult`
- [ ] **P1.4** 删除 PNJL 侧 `solver/ConstraintModes.jl`（重复定义），`PNJL.jl` 改为 `using` Models 侧定义（临时桥接）

## 8. Git 分支与提交流程建议

鉴于本次包含约 5000 行核心代码的变动，为避免单个巨型 PR 导致 Review 困难和回滚代价过大，建议将实施过程拆分为至少三个相对独立、可闭环的 PR（Pull Request）：

- **PR 1: 核心基线与 Solver 基干 (Phase 0-1)**
  - 范围：建立自动回归测试、完成 SeedStrategies, Conditions, ImplicitSolver 等 Solver 核心骨架的原生化。
  - 验收：只影响底层解算能力，可确保其在完全脱离老壳后能平替老功能。
- **PR 2: 衍生量与工作流解耦 (Phase 2-4)**
  - 范围：完成热力学导数、磁场/积分辅助件及 Scan 模块相对路径导入的剥离。
  - 验收：衍生量（Derivatives）不丢失对 `ForwardDiff.Dual` 类型的兼容，外部依赖初步干净。
- **PR 3: 全局清理与彻底退役 (Phase 5-8)**
  - 范围：所有残留 facade/bridging 层拔除，所有外部脚本/测试从 `PNJL.X` 切到 `Models.X`，最后删除 `src/models/pnjl/` 目录。
  - 验收：`PNJL` 被完全切底抹除，架构实现完全统一。
