# Solver 重构解耦总纲领与 PR 路线图

日期：2026-04-08
状态：active
适用范围：`src/models/solver/`

## 1. 背景与目标

当前 solver 子系统可用性已具备，但存在迁移期双链路并存问题：

- `Solver.jl + ProblemSpec.jl` 的主链路正在收敛；
- `ConstraintSolverFixed*.jl` 仍承担较多历史路径与模式特化细节；
- 治理语义在 `CandidateGovernance` 与 `GenericRootEngine` 之间存在并行抽象。

本总纲领目标：

- 建立单主链：`solve* -> ProblemSpec -> ModeKernel -> Governance -> Result`；
- 建立单治理语义：attempt/fallback/selection 只有一套主约束；
- 建立单职责文件边界：入口编排、问题装配、数值核、诊断分层明确。

## 2. 范围与非范围

### 范围（本轮）

- `src/models/solver/` 内部结构治理与职责收敛。
- 与 solver 直接相关的 API 文档补充（仅在公共接口语义变化时更新）。
- 单元/集成/回归测试覆盖与契约回归验证。

### 非范围（本轮不做）

- 不改动 models 其它 domain 的业务逻辑。
- 不引入新的数值后端栈替换（如整体切换 SciML）。
- 不在本轮重写物理公式或更改物理定义。

## 3. 目标架构（收敛态）

- L1 入口层：`Solver.jl`
  - 负责参数规整、策略注入、模式分发、结果封装。
- L2 问题层：`ProblemSpec*.jl`
  - 负责 mode 契约与 forward solve 装配，不内联大段执行细节。
- L3 治理层：`CandidateGovernance`（主）
  - 负责 seed pool、attempt 执行、候选排序、失败降级语义。
- L4 数值核：`ConstraintSolverFixed*.jl`、`GapSolver.jl`、`Conditions.jl`
  - 负责 residual 构造、求根、后处理与模式物理约束。
- L5 扩展层：diagnostic/implicit adapters
  - 保持兼容，不反向污染入口编排逻辑。

## 4. 四阶段 PR 路线图

### PR-1 边界硬化（低风险）

- 目标：`Solver.jl` 只保留 orchestration，不夹带治理细节。
- 产出：运行时参数收口结构、入口层职责明确化。

### PR-2 ProblemSpec 瘦身（中风险）

- 目标：拆分 `ProblemSpec.jl` 的执行编排与诊断拼装。
- 产出：`ProblemSpec` 仅聚焦契约与装配，执行细节迁移到独立文件。

### PR-3 ModeKernel 统一（中高风险）

- 目标：统一 `ConstraintSolverFixed*.jl` 骨架，收敛重复模板。
- 产出：模式求解流程统一到 `build_residual! + postprocess + hard_constraints`。

### PR-4 治理引擎合并（高收益）

- 目标：收敛 attempt/fallback/selection 到单治理主引擎。
- 产出：唯一排序规则与唯一执行入口，避免维护者抽象选择歧义。

### 阶段依赖关系

- PR-1 -> PR-2 -> PR-3 -> PR-4（严格顺序）。
- 任一阶段未完成 DoD，不进入下一阶段开发。

## 5. 跨 PR 强制协作规则

以下规则适用于 PR-1 ~ PR-4 全部任务单：

- 合并方式：`squash + delete`（PR 合并后删除远端分支）。
- 本地收尾：合并完成后本地删除已合并分支并回到 `main`。
- 开工前动作：每个任务单开工前必须从最新 `main` 新建独立分支。
- 分支卫生：保持 `main` 主分支干净，禁止在 `main` 直接开发。
- 工作区策略：本项目本轮不要求新建 worktree，默认在当前工作区按分支切换执行。

## 7. 风险与回退策略

- 风险1：行为不变重构引入隐式参数语义漂移。
  - 回退：按 PR 粒度回滚，保留前一阶段已验证分支。
- 风险2：治理收敛时排序语义变化导致边界点选解变化。
  - 回退：保留兼容开关并补充 parity regression 后再默认切换。
- 风险3：模式核统一时误伤特殊物理约束。
  - 回退：对每个 mode 单独保留 override 接口，不做硬合并。
