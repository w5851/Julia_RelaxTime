## 1. 背景与目标

`data/outputs/figures` 已有 PNJL phase、Mott/meson、transport、cross-section、literature 和诊断相关图像，但不同图族对单位、状态线型、marker、输出格式和 provenance 的记录粒度不同。已有 14 个正式根目录 manifest，尚未形成统一的 `figure_mode` 和 `style_profile` 合同。

目标是建立一个分层、可追溯、不会改变数值语义的论文级绘图生产流程：

- 正式图像统一落在 `data/outputs/figures`；
- 以冻结的 CSV/JSON 作为唯一绘图输入；
- 用 `audit`、`estimated_midpoint`、`strict`、`legacy` 区分证据和论文资格；
- 用 `candidate_origin_like_v1`、`strict_origin_like_v1`、`audit_v1` 记录视觉 profile；
- 每个新图都有输入 hash、生成器/commit、单位转换、mask/connector/interpolation policy 和输出 hash；
- Origin 只作为最终可选排版工具，不成为数值处理或插值入口。

## 2. 范围与非目标

### 2.1 本任务允许的范围

- `docs/dev/active/` 中的资产清单、合同和任务文档；
- 审核后新增的 `config/plotting/` style profile；
- 审核后新增的 `scripts/plotting/` 轻量 helper、manifest builder 和 artifact validator；
- 审核后对代表图生成新的 sibling case；
- 与上述 helper 直接相关的确定性 Python unit/contract tests；
- 最终稳定 SOP、脚本白名单和 authority map 登记。

### 2.2 明确非目标

- 不修改 solver、Maxwell、C2、reference、transport、cross-section 或 mixed-meson 数值语义；
- 不重跑 PNJL，不重生现有 canonical/reference/production CSV/JSON；
- 不覆盖、批量重绘、改名或删除 `data/outputs/figures` 中的历史图；
- 不把 `docs/analysis` 诊断图直接复制为正式图；
- 不把 C1 bracket midpoint 标成 confirmed CEP；
- 不在 Origin 中改数据、重采样、重新插值、补点或改变曲线；
- 不把所有历史绘图逻辑强行搬进一个“大绘图框架”。

### 2.3 必须保持的语义

- `mu_q` 与 `mu_B` 的区别和已有 `mu_B = 3 mu_q` 转换必须保留且显式记录；
- first-order、crossover、spinodal、CEP、unresolved、estimated 的物理含义不因样式迁移改变；
- 缺失 support、unresolved 和 nonconverged 区域不得被连成连续物理曲线；
- 原始序参量偏导峰不自动等于 crossover；在同一 `xi` 切片中，`mu_q > mu_CEP` 的峰只作诊断记录，不绘制为 crossover，且同一 `(xi, mu_q)` 不得同时赋予 crossover 与 Maxwell 物理含义；
- 端点附近跨过 CEP 筛选边界的原生采样 gap 必须记录，不得在物理面中隐式补线；`visualization-only closed` 只能作为 audit 子模式统一绘制 finite/converged Maxwell 行，若使用 display-only 三角化上限必须写入 manifest，不能把未闭合证书升级为闭合；
- 对三维相图空洞的归因先运行 v5 `diagnostic_no_triangulation`：全局禁用三角化，仅保留原生有序 support 的分段线；若缺口仍存在，则按数据 support/物理筛选解释，不能以视觉连接填补；该图仍为 diagnostic-only。
- 正式结果的计算 SHA、source run、输入数据 hash 和历史 manifest 不得被新绘图 helper 重写；
- non-fixedmu unified joint-solve 和 mixed-meson governance 不在本任务内变化。

## 4. 拟议 SOP

### 4.1 Stage 0：冻结输入和范围

1. 明确 `figure_family`、`case_slug`、`figure_mode` 和目标 style profile。
2. 只读加载既有 CSV/JSON；计算输入路径、大小、SHA-256 和字段/单位摘要。
3. 读取 calculation/source manifest，记录 `calculation_sha`、`source_run_id`、`postprocess_sha` 和 Git commit。
4. 检查目标 sibling case 是否已存在。已存在时停止，不覆盖。
5. 记录输入输出计划，不运行 solver 或任何会重生数值 CSV 的入口。

Stage 0 的失败条件是输入 hash 不匹配、单位不明、source manifest 缺失且无法解释、目标目录可能覆盖历史产物。失败时只产生 audit 记录，不进入候选或 strict。

### 4.2 Stage 1：`audit`

`audit` 用来显露数据边界：finite/nonfinite、duplicate key、converged 状态、support gap、bracket、residual、mask、被排除行和旧 connector。它可以消费诊断资产，但必须在图例、标题或 manifest 中标明诊断性质。

审计图输出到新的 `__plotv1__audit` sibling case。它不是论文图，也不会改变输入数据。C1 三维 surface 和 bracket 图优先使用此层。

### 4.3 Stage 2：`estimated_midpoint`

只有在输入显式提供 bracket 或上下界时，才允许绘制 midpoint 候选。图内和 manifest 必须同时写出：

- `semantic_status = estimated_midpoint`；
- bracket 两端和宽度；
- midpoint 的计算规则；
- 它不是 confirmed CEP 或严格物理端点的说明。

候选图可以使用 `candidate_origin_like_v1`，但不得进入论文正文草稿，也不得把 estimated marker 混入 strict series。若 midpoint 来源不完整或 bracket 不连续，退回 audit。

### 4.4 Stage 3：`strict`

strict 只接受已确认、有限、无重复、support 合格且单位明确的 series。默认交付为 SVG + 600 dpi PNG；PDF 仅在投稿或外部版式流程需要时按 case 启用。渲染前 validator 必须拒绝：

- `converged=false` 或 unresolved 行；
- 未确认 CEP、只有 bracket 的端点；
- 隐式插值、外推、跨 gap 连接；
- 未在 manifest 声明的 connector row；
- 未声明的 `mu_q -> mu_B`、MeV/GeV 或 density unit 转换；
- 缺少输入/生成器/output hash 的结果。

strict 图输出到新的 `__plotv1__strict` sibling case，必须生成 SVG 和 600 dpi PNG；PDF 不作为所有图族的硬性要求。现有历史图不因这一规则补齐或替换。

### 4.5 Stage 4：`legacy`

legacy 是历史兼容层。它只记录原图、原脚本、原 manifest 和当前可观察的旧语义，不自动改样式、不自动修单位、不自动插值修复、不自动生成新版本。历史图的“旧 connector”“旧颜色”“旧输出格式”都留在 legacy provenance 中。

如果论文仍需使用 legacy 图，必须先复制到新的候选 case，重新执行 Stage 0/1，并明确哪些变化是视觉变化、哪些变化会触及数据语义。不能直接把旧图的文件名改成 strict。

### 4.6 Origin 最终排版层

Origin 只允许接收：

- validator 已通过的 CSV/JSON 数据表；
- validator 已通过的 SVG 矢量图；若投稿流程需要 PDF，再额外导出并记录其 provenance；
- 明确的 panel/layout 配置。

Origin 不得改变数据值、排序、采样点、曲线 support、插值策略、marker 的物理状态或单位。完成排版后，必须记录 Origin 版本、输入文件 hash、工程/导出 hash、排版操作者和最终输出路径。若无法记录这些字段，产物只能是 layout preview，不能宣称 strict final。

## 5. 建议实现边界

审核通过后建议建立以下轻量层，不把图形逻辑统一成单一框架：

```text
config/plotting/audit_v1.toml
config/plotting/candidate_origin_like_v1.toml
config/plotting/strict_origin_like_v1.toml

scripts/plotting/plot_style.py
scripts/plotting/plot_manifest.py
scripts/plotting/validate_plot_artifact.py
```

这些路径已经实现并登记在正式 SOP。现有图族脚本继续拥有相图、meson、transport、literature 和诊断图的具体绘图逻辑，只调用公共 profile/manifest/validator 接口。

建议公共 helper 只负责：

- profile 解析、默认值和图族覆盖项；
- 坐标字段/单位/转换的结构化记录；
- 输入和输出 hash；
- series 状态、mask、gap 和 connector policy 的验证；
- manifest 原子写出和 schema 校验。

不建议 helper 负责：

- 调 solver 或读写 reference；
- 重新定义 phase/transport 的物理判据；
- 代替图族脚本决定数据筛选；
- 自动对缺失点做插值或补点。

## 7. 验证与治理

### 7.1 结构化验证

- 输入文件存在、大小/hash 一致；
- CSV/JSON schema、字段、单位和列映射一致；
- key 唯一、数值有限、排序稳定；
- status/mode/profile 合法且不冲突；
- gap/mask/connector/interpolation policy 与实际 series 一致；
- 输出格式、DPI、vector 标志、大小和 hash 一致；
- strict 不能包含 estimated/unresolved/nonconverged 或未声明 connector。

### 7.2 测试层选择

本任务本身只涉及后处理和文档，不改 solver 数值，因此第一阶段不触发 PNJL/Maxwell/C2/reference/transport 回归。但若实现中发现必须改变数据筛选、计算或物理判据，应立即停止绘图迁移，另立数值任务并选择相应 unit/integration/regression/validation 层。

实现 helper 后：

- `tests/unit/`：profile 解析、单位映射、状态映射、manifest schema 和错误拒绝；
- `tests/integration/`：小型冻结 fixture 从 CSV/JSON 到 sibling figure + manifest 的端到端合同；
- 不把真实生产大表、solver 扫描或批量图像放入默认 smoke；
- 代表图人工视觉审核：文字、legend、mask、断线、marker、字体嵌入和移动端/论文版面缩放；
- 运行 `scripts/dev/check_sop_governance.jl`、`check_docs_consistency.jl`、`check_script_entrypoints.jl` 和适用的 Python syntax/contract checks。

## 8. 风险与回退

| 风险 | 早期信号 | 缓解 | 回退 |
| --- | --- | --- | --- |
| 隐藏单位转换 | `mu_MeV`、`muB_MeV`、`rho` 在不同脚本含义不同 | 将 source/display unit 和 transform 强制写入 manifest | 只保留 audit/legacy，暂停 strict |
| connector 行被当作物理点 | 输出曲线穿过缺失 support 或 CEP | strict 禁止未声明 connector；保留旧 connector 为 legacy | 退回 source asset，不输出 strict |
| midpoint 被误称 CEP | bracket 只有上下界或 `found=false` | 独立 `cep_bracket`/`estimated_midpoint` state 和 caption | 只生成 audit |
| gap 被连接 | 三角面/一维曲线跨越稀疏区 | mask/gap policy fixture 和 row-level validator | 使用断线或不生成图 |
| 字体/矢量输出漂移 | 不同机器 PDF 字体或尺寸不同 | 记录 resolved font、runtime、vector/DPI；视觉审核 | 保留 PNG audit，修 profile 后再出 candidate |
| 历史图被覆盖 | 输出路径命中已有 case | 目标目录存在即失败，使用新 sibling slug | 不执行写图 |
| 大规模迁移扩大范围 | 一次触及大量旧脚本/旧图 | 按代表图和活跃生成器分批，旧图保持 legacy | 停在 M1 或 M2，不批量重绘 |
