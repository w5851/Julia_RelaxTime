- 介子质量、介子数密度、介子热力学和 phase-shift 派生路线；

- 已有 benchmark 与 probe：
  `scripts/perf/relaxtime/bulk_derivative_context_probe.jl`、
  `scripts/perf/pnjl_phase_thermal_quadrature_probe.jl`、
  `benchmark/pnjl/single_point_solver_perf.jl`、

### 非目标

- 不再把 FixedRho 8D 改 6D 作为性能候选：既有 A/B 已显示稳定性下降，直接拒绝；
- 不重新重复已有 ThermoJet/显式高阶导数方向的同口径试验，除非发现 workload 或调用路径不匹配；
- 不把 PALC 作为默认生产 backend。历史结果只支持“尚未表现出同口径性能优势”，不能据此声称普遍更慢；

- 不把 `rs_reduced_adaptive` 自动视为性能优化。它更可能是极端参数下的稳定性/验证 oracle；
- 不在磁场语义未闭合前做 fused Landau pass 或其他可能改变物理含义的性能改动。

## 3. 当前证据与判断边界

### 已有事实

1. C0 提供的运行事实为：2,857,345 个 `unique_solves`、5,166,945 个 point requests、
   2,309,600 个 cache hits，约 9 h 44 min；这些数字描述 cache-miss/request 层，
   不等于实际 NLsolve invocation 数量。
2. 既有 bulk derivative context probe 在 `T_fm=0.5, mu_fm=1.5, xi=0,
   p_num/t_num=12/6` 的短样本中记录过 `0.0817666 s -> 0.0035349 s`、约 `23.13x`，
   额外 primal solve `5 -> 0`、Jacobian 构建/分解 `5 -> 1`。这对 bulk/transport
   derivative 子路线是强的局部实现收益证据，不是全仓库或 C0 的总耗时证明。
3. 已有 A/B 记录显示 ThermoJet/显式 Hessian 类深层 solver-kernel 路线没有稳定明显收益；
   在没有新 workload 证据前，不重复投入相同实验。
4. `rs_reduced_adaptive` 的价值首先是低温/极端参数附近的数值稳定性，不能从“自适应”
   这个名字推导其一定更快；默认性能比较仍以实际 benchmark 为准。

### 注释问题的处理结论

- About 指向的所有计算路线都纳入候选池，但按“核心程度、已有收益、物理风险”排序；
  transport/meson 的路径特有优化保持低优先级。
- 重复代码分成两类：会造成重复求解/重复积分的运行时重复；以及主要增加可读性、
  维护风险和开发者心智负担的结构重复。后一类可单独作为重构任务，不能虚报成性能收益。
- shared bulk derivative/base context 已在主线实现；A/B-0 只复核这一已有路径的局部收益，
  不代表需要重新实现 context。后续候选是评估能否把同一 context 的复用范围扩大到更多
  派生量和工作流。ThermoJet 的“同时一阶/二阶导数”并非当前已证实的收益点；NLsolve
  可接显式 Jacobian，但若构造 Jacobian/高阶 jet 本身抵消了减少的残差评估，就不应采用。
- FixedRho 8D -> 6D 已因稳定性下降排除，不再进行性能权衡。
- magnetic gap 与 magnetic omega 的物理语义一致性属于稳定性问题，优先于任何磁场热点
  优化；先只读审计，审计通过后再决定是否值得短 benchmark。
- sampling 优化必须给出覆盖/误差 certificate。高精度全域结果不是永远唯一方案，但在
  未有可靠的自适应误差界、分支检测和局部补点规则前，不能用稀疏采样替代正式验证层。

### 6A. Magnetic 单点成本诊断（2026-08-19）

本节保留 2026-08-19 的历史单点、低节点成本基线；当时不修改生产实现、不调用
`solve_magnetic_gap`，不运行 magnetic scan、C0/C1/C2。其 finite-difference
center-elision 记录不再代表当前生产 residual，也不作为新的实现候选。
A/B-M1 的具体候选是“显式 `n_max` 时跳过有限差分残差中未参与梯度构造的中心
`Omega(x)` 评估”，下文简称 **center-elision**；它不是改变中心差分公式、步长、状态
维数或求解器方法。

- 参数：`T=150 MeV`、`mu_u=mu_d=mu_s=60 MeV`、`eB=20000 MeV^2`、`xi=0`；
  `p_num=4`、`t_num=4`、`pz_max=5`、显式 `n_max=1`；固定五维状态
  `(-0.03,-0.03,-0.04,0.2,0.2)`；warm-up 后各 3 次样本。
- 命令只测 `Models.omega`、`Models.magnetic_gap_residual` 和
  `Models.model_rho`，没有启动完整 equilibrium scan。
- 结果（历史 baseline）：`Omega` 中位 `0.0044 ms`、残差中位 `0.0648 ms`、净密度中位
  `0.0070 ms`；分配分别为 `16/48/32 bytes`。
- 结构事实（历史 finite-difference baseline）：当时五维 residual 在显式 `n_max` 时仍计算中心项，再加
  五个方向的正负扰动，即约 11 次 Omega 评估；center-elision 只保留 10 次扰动评估。
  当 `n_max=nothing` 时，中心项仍用于推断 `local_n_max`，因此不能无条件删除。该测量
  与 `0.0648/0.0044` 的局部比值一致，但不等于默认节点或 NLsolve 每次迭代的生产耗时。

证据边界：这是 magnetic solver kernel 的历史成本结构基线，不是“显式 Jacobian、共享
thermo context 或 fused Landau pass 已有收益”的证明。当前 AD 默认的稳态收益来自同一
进程内的独立 A/B 记录（AD `0.553 ms`、FD `9.436 ms`，低节点）；不能外推生产精度或
完整磁场扫描 wall time。后续若研究其他磁场 kernel，仍须保持同一五维根、分支标签、
残差和 `n_max`，并显式记录 Omega 调用数、NLsolve f/g calls、iterations、attempt/fallback
和 quadrature evaluations。

## 6. 风险与回退

| 风险 | 触发信号 | 处理 |
|---|---|---|
| 短 benchmark 触发意外长调用 | 首个样本超过预估上限、输出无进展 | 立即停止该进程，降低点数/样本，不运行扫描 wrapper |
| shared context 改变分支 | residual、质量、Omega 或 branch label 不一致 | 仅保留诊断结果，拒绝优化，不修改 production |
| 自适应积分更稳但更慢 | wall time 增加且数值更稳定 | 把它定位为 stability oracle，不做默认性能改动 |
| 路线特有优化收益过小 | 总链路占比低于优先级门槛 | 留在低优先级 backlog，不阻塞核心路线 |
| 结果与历史记录不具同口径 | 节点、seed、postprocess 或 warm/cold 状态不同 | 降低证据等级，禁止跨路线外推 |
