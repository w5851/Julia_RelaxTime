## 2. 现状共性抽象（跨模型）

不管是 PNJL/旋转/各向异性等变体，求解流程的共性可抽为：

1. **状态变量**：`x`（序参量向量，维度随模式而定）。
2. **外参容器**：`params`（如 `T`, `mu`, `rho`, `omega`, `xi` 等，可扩展）。
3. **目标条件**：
   - 驻点条件：`∂Omega/∂x = 0`
   - 或约束扩展条件（固定 `rho`/`s`/`sigma`/非对称条件）
4. **数值策略**：连续化热启动 + 多初值竞争 + 失败回退。
5. **结果治理**：硬约束筛选 + 候选择优 + 诊断可追溯。

这意味着“模型差异”应主要落在残差构造和可观测量计算，不应扩散到调度流程。

## 3. 先行约束（实现前必须锁定）

### 3.1 架构约束

1. 统一入口：`Models.solve* / solve_constraint / scan_workflow` 为唯一主线入口。
2. 流程层与物理层分离：
   - 物理层只负责 `Omega`、残差、派生量。
   - 流程层只负责种子、求解、筛选、诊断、扫描编排。
3. 同类职责单一归位：避免 `constraint_solver.jl` 与 `solver/*.jl` 长期并行重复。

### 3.2 参数约束

1. 扫描/外参统一使用命名容器（首选 `NamedTuple` 语义）。
2. 模型按需取字段，不需要的字段不参与模型计算。
3. 参数扩展（如 `omega`, `xi`）不应要求改求解框架主体。

### 3.3 AD/隐式微分约束

1. 核心残差必须可提供“显式参数接口”版本。
2. 可在流程层包装闭包，但不可只有闭包接口。
3. 新接口需对自动微分/隐式微分保留兼容通道。

### 3.4 治理约束

1. 兼容层可短期存在，但需标注迁移终点和删除门槛。
2. 每一波收敛都要配套测试与文档证据。
3. 不做一次性重写，采用可回退的增量迁移。

## 4. 目标分层草图

### L0 物理模型层（Model Physics）

- 输入：`x`, `params`
- 输出：`residual`, `Omega`, 派生量
- 典型内容：`pnjl_physics/*`, 变体模型 core

### L1 方程构造层（Equation Builder）

- 把模式（FixedMu/FixedRho/FixedEntropy/...）映射为统一残差问题描述
- 负责拼装约束方程和尺度归一化

### L2 求解策略层（Solve Policy）

- 连续化策略、初值策略、多候选求解、失败回退
- 底层引擎可切换（NLsolve/后续其他引擎）

### L3 候选治理层（Candidate Governance）

- 硬约束规则集
- 候选筛选与择优
- 输出稳定的诊断结构（失败原因、选优原因、候选计数）

### L4 工作流与扫描层（Workflow / Scan）

- 统一扫描入口，`model + mode + params_grid`
- 只做编排，不内嵌模型特化求解细节

## 5. 与当前实现的收敛方向（不改代码版）

1. `constraint_solver.jl`：保留为“约束求解主干”的过渡承载点。
2. `solver/*.jl`：逐步成为统一策略/模式/引擎的稳定承载点。
3. `gap_solver.jl` / `implicit_gap.jl`：明确定位为基础求解能力，不再承载高层编排。
4. `scans/*.jl`：向“模型参数化统一扫描入口”靠拢。

## 6. 建议迁移波次

### Wave-A（先立规）

- 冻结接口契约：参数容器、残差签名、候选诊断结构、约束规则接口。
- 输出“接口对照表”（旧接口 -> 新接口）。

### Wave-B（并轨）

- 把分散的模式求解入口并入统一策略层。
- 保留兼容壳，但新功能只进主线。

### Wave-C（扫描收敛）

- 脚本和工作流改为 `model` 驱动。
- 删除模型特化扫描 SOP 的重复路径。

### Wave-D（清理与固化）

- 删除兼容壳与重复入口。
- 文档/测试/治理脚本全部更新到新口径。

---

## 7. 验收口径（DoD）

1. 新增模型参数字段时，不改求解框架主干。
2. 同一套求解流程可覆盖多模型/多约束模式。
3. 多初值+约束筛选+择优链路有稳定测试。
4. 扫描入口不再按模型复制 SOP。
5. 兼容层删除有明确完成证据。

## 9. 外部审阅意见核验（结论）

以下是对你提供的审阅点的核验结果：

### 9.1 L1 方程构造层抽象（属实，必须纳入）

- 结论：属实，应在 Wave-A 强制落地。
- 依据：当前 `src/models/constraint_solver.jl` 与 `src/models/solver/ImplicitSolver.jl` 对不同模式存在分支和重复路径，L2 若直接感知模式会继续耦合。
- 纳入措施：新增“统一问题描述结构”约束。

建议最小结构（示意）：

```julia
ProblemSpec(
    mode,
    x_dim,
    param_dim,
    residual!,
    unpack_solution,
    postprocess,
)
```

### 9.2 L3 硬约束/择优规则具体化（属实，必须纳入）

- 结论：属实，应前置定义接口规范。
- 依据：当前已有 `default_hard_constraint_rules` 与 `select_pressure_max_candidate`，但“连续性优先 vs 热力学势优先”尚未显式规则化。
- 纳入措施：在 Wave-A 仅先冻结规则接口，不预先塞满规则实现。

建议接口：

```julia
hard_rule(candidate, params) -> (ok::Bool, reason::Symbol)
selector(candidates, params, context) -> selected_index
```

### 9.3 AD/隐式微分签名建议（部分属实，建议调整后纳入）

- 结论：需要纳入，但不建议固定成 `residual!(F, x, params, mode)` 这一唯一形态。
- 原因：本仓库已有基于多重派发的 `mode` 类型体系（`FixedMu` 等），更自然方案是“`mode` 进入上下文/问题描述”，而不是强制每个残差函数都显式带 `mode` 参数。
- 纳入措施：约束改为“必须有显式参数接口 + mode 可被显式识别（通过 `ProblemSpec` 或方法签名）”。

### 9.4 兼容层管理（属实，必须纳入）

- 结论：属实，应在 Wave-A 直接产出迁移映射表和删除门槛。
- 纳入措施：新增“旧接口 -> 新接口 -> 删除条件”台账条目，并在 Wave-B 起打 `@deprecate` 或等价治理标记。

### 9.5 风险点核验

1. 可变维度 `x`：属实。`FixedMu` 与其他模式维度已不同，L2 必须显式携带维度信息。
2. AD 与分支：属实。应避免把不可微判断塞进残差主路径。
3. 多初值配置复杂：属实。`SeedStrategies` 已较大，需用抽象接口收敛而非继续平铺参数。
