# 介子热力学扩展任务单

更新日期：2026-05-07

当前状态：设计中；该任务单用于承接 `meson pressure / EOS / 文献对照 / channel 扩展` 这条后续独立主线，目标是把“介子热力学”从当前分析性能力推进为正式物理能力与正式 workflow。

> 目的：在不打断当前 transport 主线产品化节奏的前提下，提前把介子热力学扩展的范围、依赖、验证策略与能力边界固定下来，避免后续直接跳入实现时把 EOS、文献对照、channel 扩张混成一团。

---

## 1. 背景与目标

当前仓库在 `meson density / BU / phase-shift` 主线已经具备：

- [x] `stable / strict BW / current BU / generalized BU reference` 四条 workflow
- [x] `pi / K` 介子数密度与 `K/pi` 比值计算链
- [x] `plot_review + regression` 的兜底治理方案
- [x] `2+1 flavor + BU/phase-shift` 机制层文献梳理
- [x] “六费米子同构层参考”与“机制层参考”分层结论

但当前仍缺一条正式的“介子热力学 / EOS 扩展”主线：

- [ ] 缺少 mesonic pressure 的正式计算入口
- [ ] 缺少 pressure/EOS 结果的正式输出、结果目录与 README 契约
- [ ] 缺少 pressure/EOS 的 regression / validation 分层治理
- [ ] 缺少对“是否需要新增 meson channel”的明确判定口径
- [ ] 缺少把现有 BU/phase-shift 能力升格为 EOS workflow 的任务分解

本任务单的目标是：

1. 明确介子热力学扩展的物理范围与非范围；
2. 固化 pressure / EOS / 文献对照 / channel 扩展的执行顺序；
3. 设计正式 workflow、结果出口与测试治理边界；
4. 为 transport T1 完成后的下一个物理能力主线做好直接落地准备。

## 5. 需求收口

### 5.1 正式物理能力目标

本主线最终希望形成以下正式能力：

- [ ] 介子 pressure 计算入口
- [ ] 总 pressure 中 mesonic contribution 的独立导出
- [ ] 介子 pressure 对 EOS 组合量的影响评估
- [ ] `pi/K` 主通道下的 canonical 扫描与图形
- [ ] 后续可扩展到更广 scalar/pseudoscalar channel 的能力框架

### 5.2 channel 扩张判断

当前第一阶段不要求一开始就做 full nonet 全展开，但需要显式判断：

- [ ] `pi/K` 是否足够支撑第一版 mesonic pressure / EOS workflow
- [ ] 若不够，优先新增哪些 channel
- [ ] channel 新增应是：
  - scalar partner (`sigma / a0 / kappa`) 优先
  - 还是 pseudoscalar nonet 先补齐

当前建议口径：

- [x] 第一阶段以 `pi/K` 先打通正式 pressure workflow
- [ ] 第二阶段再评估是否必须纳入 `sigma / a0 / kappa / eta` 等 channel
- [ ] 若 channel 扩张只改变量级、不改变 workflow 结构，应拆成后续子任务而不是阻塞第一版上线

### 5.3 结果组织目标

- [ ] 需要正式的 CSV / figures / README / provenance 目录
- [ ] 需要用户可直接消费的 `data/` 层 canonical 结果
- [ ] 需要面向测试层的 baseline 资产
- [ ] 需要面向人工趋势比较的 plot-review 资产

### 5.4 文档同步治理

- [ ] 当 EOS / mesonic pressure 的能力边界稳定后，需要同步更新：
  - `README.md`
  - `docs/api/`
  - `docs/guides/`（若新增正式脚本入口或结果目录口径）
  - GitHub 项目简介 / 仓库简介（若新增能力已经足够稳定、值得对外宣称）
- [ ] 在能力边界尚未稳定前，不提前把实验性路径写成正式对外能力

### 5.5 validation / regression / data-layer 三层分工

- [ ] 若后续找到与当前计算路径**完全匹配**的文献 target：
  - 用户负责手动提取目标数据；
  - 项目侧负责实现 `tests/validation/` 层的 formal validation；
  - 文档中需写清 target 路径定义、模型差异与比较字段。
- [ ] 若后续仍找不到完全匹配的文献 target：
  - 必须实现 regression，保证本项目按当前计算路径得到的 EOS 结果不因后续版本而无意漂移；
  - 必须生成 plot-review 图，供用户人工对照文献中的定性趋势；
  - 不得把这种情形包装成 external validation gate。
- [ ] 对稳定且常用的数值结果：
  - 可以沉淀到 `data/` 层作为用户参考基线；
  - 但必须与 `tests/regression/`、`tests/validation/` 使用的测试基线明确区分。

## 6. 分阶段任务单

### Phase T3.1：pressure kernel 与 workflow 设计

- [ ] 明确 mesonic pressure 的主实现入口
  - 验收：给出“以哪个入口消费 propagator / polarization / phase shift”的单一路线

  - 验收：写清当前默认是 `current BU`、`generalized BU reference`，还是两者并存

  - 验收：至少列出 `P_meson`、`P_total`、必要时的 `I=(ε-3P)/T^4` 或等价组合

### Phase T3.2：最小 canonical case

- [ ] 选择第一批 canonical case
  - 推荐：`mu_B = 0` 温度扫描
  - 验收：固定 `T` 范围、步长、workflow 与输出字段
- [ ] 选择第一批对照图
  - 验收：至少有 `P_meson(T)`、`P_total(T)`、必要的 ratio/difference 图
- [ ] 明确与现有 meson-density workflow 的关系
  - 验收：写清哪些输入/中间量可以共用，哪些是新增输出

### Phase T3.3：regression / plot-review / validation 分层

- [ ] 设计 point-level regression
  - 验收：确定锁哪些 scalar 输出字段
- [ ] 设计 path-level regression
  - 验收：确定最小温度路径或 EOS case
- [ ] 设计 plot-review 目录
  - 验收：目录结构、文件命名、README 模板明确
- [ ] 明确 validation 升格门槛
  - 验收：至少写清文献 target 需满足哪些同构条件
- [ ] 明确 user-facing `data/` 参考基线与 test baseline 的分层
  - 验收：写清两者目录、用途与更新准入差异

### Phase T3.4：channel 扩张决策

- [ ] 用首版 `pi/K` pressure 结果判断是否需要新增 channel
  - 验收：形成“现阶段足够 / 必须扩张”的明确结论
- [ ] 若需要新增 channel，确定最小新增集合
  - 验收：给出优先级与理由
- [ ] 若不需要立即扩张，也写清当前边界
  - 验收：说明哪些物理结论在 `pi/K-only` 下仍不能过度外推

### Phase T3.5：正式 workflow 与 data 资产

- [ ] 固化脚本入口
  - 验收：具备正式 CLI 或脚本主入口
- [ ] 固化 `data/outputs/results/` 正式目录
  - 验收：每个 canonical case 都有 CSV + figures + README + provenance
- [ ] 评估是否需要在 `data/` 层沉淀用户参考结果
  - 验收：给出“沉淀 / 暂不沉淀”的明确判断
- [ ] 能力边界稳定后同步更新 README / docs / 项目简介
  - 验收：至少列出已更新的文档入口与新增能力描述口径

## 8. 测试与验收标准

### 8.1 regression

- [ ] 至少有一组 point-level baseline
- [ ] 至少有一组 path-level canonical regression
- [ ] 不得通过放宽容差掩盖 pressure kernel 漂移

### 8.2 validation

只有满足以下条件时才允许进入 `tests/validation/`：

- [ ] 文献 target 的路径定义可重建
- [ ] 文献模型与当前项目差异已分层说明
- [ ] 数值比较可自动化
- [ ] 结果不是只能做定性趋势比较

### 8.3 plot-review

- [ ] 若 external target 只能做趋势比对，应进入 `plot_review`
- [ ] README 必须明确“这不是 validation gate”
