# F4.1 首个外部验证样本与提取方案

更新日期：2026-05-03

目的：选定第一篇外部验证目标文献，并明确其结果能否自动化提取；对于不能稳定自动提取的部分，给出用户最小人工操作方案。

## 1. 首个样本选择

当前建议优先选择：

- `Blaschke:2019col`
- 文献文件：
  - `paper_lib/docs/papers/介子数密度(及其比值)/Blaschke 等 - 2020 - Using the Beth–Uhlenbeck Approach to Describe the Kaon to Pion Ratio in a 2 + 1 Flavor PNJL Model.pdf`

选择理由：

1. 与本项目当前主线最接近的 BU 文献之一；
2. 文中明确写出：
   - partial densities
   - generalized BU replacement
   - `K^+/\pi^+` / `K^-/\pi^-`
   - freeze-out line / critical line
   - `μ_\pi = 100, 134.5 MeV`
3. 它很适合做未来 charged / freeze-out 子链的第一份外部验证样本。

## 2. 这篇文献里哪些内容可自动提取

### 2.1 可自动提取

当前可较稳定自动提取的部分是**语义元数据**，例如：

1. 目标物理量：
   - `K^+/\pi^+`
   - `K^-/\pi^-`
2. 公式口径：
   - partial densities
   - generalized BU
3. 场景口径：
   - chemical freeze-out line
   - critical line
   - `μ_\pi = 100 MeV`
   - `μ_\pi = 134.5 MeV`
4. 图的角色：
   - Figure 3: `T-\mu_q` plane ratio map
   - Figure 4: ratio vs `sqrt(s_NN)` compared with experiment

这些信息当前已经可以从本地 `.txt` 文本稳定抽出来。

### 2.2 不适合直接全自动提取

当前**不建议直接承诺全自动提取**的部分，是图上的数值曲线本身，尤其是：

1. Figure 4 中多条实验点 + 多条理论曲线
2. shaded region（anomalous mode contribution）
3. 同图中不同 `μ_\pi`、不同 scan line 的多条重叠曲线

原因：

1. PDF 没有现成表格给出这些点值；
2. 本地图像是论文图，不是原始数据文件；
3. 即使能做图像数字化，也容易在：
   - 曲线交叉
   - 图例遮挡
   - shaded band
   - 多面板
   上失真；
4. 如果没有人工确认，自动提取结果不适合直接升格成 regression 真值。

## 3. 当前最合理的自动化边界

当前更稳妥的做法是：

1. **自动提取语义元数据**
2. **人工最小化提取数值点**
3. 再由项目侧把这些人工确认点结构化成 CSV

也就是说：

- 自动化做“结果是什么、属于哪种口径、图在哪”
- 人工只做“点值确认”

## 4. 用户最小人工操作方案

若要把 `Blaschke:2019col` 变成第一份外部验证样本，用户最小只需要做下面这一步：

1. 对文中目标图做一次人工数字化导出

当前优先建议的目标图是：

- Figure 4 右 panel

但需要先澄清其图结构：

1. `K^+/\pi^+` 不是单条曲线；
2. 文中图注明确说明：
   - 黑线是 `K^+/\pi^+`
   - 薄线对应 `μ_\pi = 100 MeV`
   - 厚线对应 `μ_\pi = 134.5 MeV`
   - 两条 `K^+` 线之间的阴影区域对应 anomalous mode contribution
3. 因此 `K^+/\pi^+` 更适合按 `band/range` 处理，而不是作为首个最小单曲线样本。

基于这一点，当前更优先建议提取的曲线改为：

1. `K^-/\pi^-`
2. `μ_\pi = 100 MeV`
3. right-panel thin red dotted line

原因：

1. 它仍属于文献最终对实验比较的结果层；
2. 不带 `K^+` 那种阴影范围；
3. 更适合做第一份最小人工样本。

### 推荐的最小人工步骤

可用任一你顺手的 digitizer 工具，最小步骤如下：

1. 打开 Figure 4 右 panel 图
2. 只选一条目标曲线：
   - `K^-/\pi^-`
   - `μ_\pi = 100 MeV`
3. 做坐标轴标定：
   - `x = sqrt(s_NN) [GeV]`
   - `y = ratio`
4. 导出为 CSV
5. 只要两列：
   - `x_value`
   - `y_value`

## 7. 当前结论

对于 `Blaschke:2019col` 这类文献：

1. **语义层可以自动提取**
2. **数值曲线层不建议直接全自动提取**
3. 最合理的方案是：
   - 项目自动完成口径整理与结构化框架
   - 用户只做最小人工 digitize
4. 对于 `Figure 4` 右 panel：
   - `K^+/\pi^+` 建议后续按 `band` 的上下边界分别提取；
   - 首个最小样本优先改为 `K^-/\pi^-` 单曲线。

## 9. 对这份 WPD 导出的最小清洗规则

由于 WPD 导出是多数据集并列表，且可能在尾部混入不连续的残留点，当前项目侧采用最小清洗规则：

1. 每个数据集按 `X/Y` 成对拆分；
2. 跳过空列或不完整行；
3. 保留各自 `x_value` 严格递增的主段；
4. 将尾部非单调回跳点记入 import report，而不是静默吞掉。

本次导出中，已识别到：

- `mu_100_K/pi+with_anomalous` 尾部有 `1` 个明显非单调尾点，被作为脏数据剔除；
- 两条 `K^-/\pi^-` 曲线则主要是尾部空白补列，不影响主段。

## 10. 对 Figure 4 右 panel 扫描路径可复现性的当前判断

当前信息**足以做结果层 target 对照**，但**还不足以精确复现其扫描路径本身**。

更具体地说：

1. 我们已经知道它不是简单的单一 `T` 扫描；
2. 文中语义表述表明它涉及：
   - phase transition / critical-line 段
   - 以及拼接上的 straight constant-temperature 段
3. 但仅凭 Figure 4 右 panel 的结果曲线，无法唯一反推出：
   - 每一段对应的精确参数化路径
   - 拼接点位置
   - `sqrt(s_NN) -> (T, \mu_B, \mu_\pi, \mu_s)` 的完整映射

因此当前建议是：

1. 把这些 CSV 先作为**结果 target** 管理；
2. 不把它们误当成“已知精确扫描路径”的 regression 真值；
3. 若后续进入 charged / freeze-out 子链正式复现，再单独补：
   - Figure 1 或对应路径图的 digitize
   - 文中 freeze-out / critical-line 参数化规则
   - `\mu_s` / `\mu_\pi` 的具体构造口径
