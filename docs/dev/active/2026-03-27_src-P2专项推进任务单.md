# src P2 专项推进任务单（防偏移）

## 1. 目的

本任务单用于集中跟踪 `src` 体检报告中的 P2 项，避免后续推进时与原始结论偏移。

来源基线：
- `docs/dev/active/2026-03-27_src体检结果报告_10维度.md`

## 2. P2 项范围（仅来自体检报告）

### P2-1：架构边界收敛（Main.* 直连收敛）

**目标**
- 在不改外部 API 的前提下，减少 workflow 对 `Main.Models` 的散点直连，先收敛到可替换薄封装。

**任务**
- [ ] 盘点 `src/models/workflows/TransportWorkflow.jl` 中 `Main.*` 直接依赖点。
- [ ] 引入单点依赖访问 helper（或局部 facade），不改变行为。
- [ ] 为迁移点补最小回归测试（至少 workflow selector 或对应 smoke 路径）。

**验收**
- [ ] 行为不变（对应 unit smoke 通过）。
- [ ] 依赖入口更集中，可枚举。

---

### P2-2：并发状态治理（scan jobs 清理策略）

**目标**
- 控制 `_PNJL_SCAN_JOBS` 长 session 累积风险，补 lifecycle 清理机制。

**任务**
- [x] 设计并实现清理策略（TTL 或数量上限，二选一或组合）。
- [x] 保证清理不破坏进行中任务与结果查询契约。
- [x] 补单测：过期/超限清理、进行中保留、结果可见性边界。

**验收**
- [x] 新增清理行为在测试中可复现。
- [x] 不引入现有 scan jobs 契约回归。

---

### P2-3：观测性统一（结构化字段最小规范）

**目标**
- 统一关键 warning/error 响应字段，便于复盘与检索。

**当前状态**
- [x] `pnjl_scan_jobs` 响应已增加 `diagnostics(job_id/kind/job_status/error_type)`。

**后续任务**
- [x] 形成最小字段规范（建议：`job_id/profile/T/mu/xi/error_type`，按模块取子集）。
- [x] 在 workflow 关键 warning 路径落地同口径字段（不扩 scope）。
- [x] 补对应断言测试或日志契约测试。

**验收**
- [x] 至少两个关键链路字段口径统一。
- [x] 文档化字段说明并在 PR 描述引用。

## 3. 非目标

- 不做大规模性能重构。
- 不在本任务单引入新的物理模型与算法替换。

## 4. 验证与交付

每个子项完成后至少执行：
- `julia --project=. -e 'ENV["UNIT_FILES"]="simulation/test_pnjl_scan_jobs.jl"; include("tests/unit/runtests.jl")'`（涉及 scan jobs 时）
- `julia --project=. -e 'ENV["UNIT_PROFILE"]="smoke"; include("tests/unit/runtests.jl")'`
- `julia --project=. scripts/dev/check_docs_consistency.jl`（文档变更时）

## 5. 执行顺序建议

1. P2-2（并发状态治理）
2. P2-3（观测性统一，补齐剩余链路）
3. P2-1（架构边界收敛）
