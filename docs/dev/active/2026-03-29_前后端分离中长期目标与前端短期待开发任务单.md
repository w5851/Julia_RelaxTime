# 前后端分离中长期目标与前端短期待开发任务单

## 1. 背景与目标

- 当前形态为同仓一体化（后端服务静态文件 + API），已具备前后端接口分层雏形。
- 当前阶段无远程算力/服务器，前端开发与计算默认在同一台机器完成（localhost 模式）。
- 目标是先完成“前端仅依赖 API 契约”的稳定联调，再逐步落地可运维的前后端分离部署。

## 1.1 本期策略（80/20）

- 80% 资源用于本机可用性：优先打通本机任务闭环与前端体验。
- 20% 资源用于最小远程兼容：仅做 `API_BASE_URL` 配置解耦、超时/重试与错误预留，不引入生产级复杂能力。

## 2. 现状盘点

- 后端已具备基础 API 路由与任务化扫描能力（异步 jobs）。
- 前端已有 API 调用与基础页面，但功能仍偏演示，缺少完整任务工作流。
- 核心扫描能力目前主要通过 `run_*.jl` 脚本驱动，适合作为编排入口，不适合作为前端长期契约层。

## 4. 中长期 DoD（完成定义）
