# PALC 连续路径求解接口设计

创建日期：2026-06-18

## 1. 背景与目标

`FixedAsymmetricRho` 的生产诊断已经确认：在一阶相变或 S 形多根区域，多个 equilibrium root 可以同时满足密度约束和极小 residual，但 pressure 不同。旧生产路径把上一 rho 点解作为唯一 seed 时，可能稳定跟随低压根，导致物理解选择错误。

PALC spike 的结论进一步澄清了职责边界：

- PALC 是连续路径/分支追踪策略，不是单点 root solver 的直接替代。
- 单条 PALC 分支不能自动解决多根问题；必须先发现多个 anchor root，再分别延拓。
- ground-state 语义仍需要 pressure max under constraints 的 branch governance。

本设计的目标是定义一个可进入 `src/models` 的实验性连续路径求解接口，使 PALC 后续可以作为新的 continuation backend 接入，同时保留现有单点 `solve` / `solve_multi` 契约。

## 2. 范围与非范围

### 范围

- 设计 `solve_path` 风格的内部实验接口。
- 明确 `PathProblem`、`ContinuationStrategy`、`AnchorStrategy`、`BranchPolicy`、结果对象的职责。
- 首个目标 path 为 `FixedAsymmetricRho` 的 rho 路径，覆盖 `T=120, rho=0.35` 与 `T=130, rho=0.80` 的多根场景。
- 明确 PALC 与现有 `solve_multi`、`SeedStrategy`、ProblemSpec selector 的关系。
- 给出测试、回归、迁移门槛。

### 非范围

- 本阶段不把 BifurcationKit 加入根 `Project.toml`。
- 本阶段不导出稳定 public API。
- 本阶段不修改 `Models.solve` / `Models.solve_multi` 的现有签名和语义。
- 本阶段不替换 `run_tmu_scan`、`run_trho_scan` 或 phase pipeline 默认路径。
- 本阶段不处理 `FixedRho`，除非后续证据显示其存在同类多根分支治理问题。

## 3. 现状盘点

### 已有能力

- `Models.solve`：单点求解，返回 `SolverResult`。
- `Models.solve_multi`：多初值单点求解，适合 ground-state pressure selection。
- `ProblemSpec`：统一约束求解主链，支持 selector / semantic_mode。
- `RootProblemSpec` / `solve_root_continuation`：低层通用 root tracker，但不表达物理路径、多分支 PALC 或 pressure branch governance。
- `scripts/analysis/pnjl_bifurcation_spike/run_fixedasymrho_multibranch_palc.jl`：已验证 multi-branch PALC 可在两个目标场景发现并追踪高压/低压两支。
- `scripts/relaxtime/run_combined_meson_density_scan.jl --path trho_asymmetric`：已临时修复为 all-attempt pressure-governed production path。

### 缺口

- 缺少统一的“路径问题”对象，当前 scan 脚本直接编排参数顺序、seed 传递和 branch policy。
- `SeedStrategy` 只能表达单点初值，不应承担 PALC 这类路径延拓语义。
- 缺少跨分支结果结构，无法同时表达 anchor roots、continuation branches、ground-state selection。
- 缺少稳定的 path-level diagnostics 字段：branch id、source、selected reason、candidate branch count、fallback source 等。

## 4. 接口分层

### 4.1 PathProblem

`PathProblem` 只描述“沿哪个物理参数路径求解”，不决定用哪种算法。

建议新增内部类型：

```julia
abstract type AbstractPathProblem end

struct FixedAsymmetricRhoPath <: AbstractPathProblem
    T_fm::Float64
    rho_values::Vector{Float64}
    ud_ratio_target::Float64
    s_target::Float64
    xi::Float64
    p_num::Int
    t_num::Int
end
```

首期只要求 `FixedAsymmetricRhoPath`。后续如 `FixedMuPath`、freezeout path、isentropic path 可复用同一接口。

### 4.2 AnchorStrategy

`AnchorStrategy` 负责在路径上的一个或多个 anchor point 找到 distinct roots。

建议接口：

```julia
abstract type AbstractAnchorStrategy end

struct SeedPoolAnchor <: AbstractAnchorStrategy
end

struct MultiSeedAnchor <: AbstractAnchorStrategy
    evaluate_all_attempts::Bool
    root_distance_tol::Float64
end

struct ProductionLikeAnchor <: AbstractAnchorStrategy
    source_param::Float64
    step::Float64
    root_distance_tol::Float64
end

struct CompositeAnchor <: AbstractAnchorStrategy
    strategies::Vector{AbstractAnchorStrategy}
    root_distance_tol::Float64
end
```

`SeedPoolAnchor` 表示 `SeedContinuation` 的实际 MVP 行为：上一点解与 `MultiSeed` catalog 共同组成单点 seed pool，但不做 distinct anchor-root discovery。multi-anchor discovery 仍保留给隔离 PALC adapter；如果根环境 `SeedContinuation` 收到 `MultiSeedAnchor`、`ProductionLikeAnchor` 或 `CompositeAnchor`，应明确报错，避免诊断字段误报。

PALC adapter 的默认 anchor policy 应等价于 spike：

```julia
CompositeAnchor([
    MultiSeedAnchor(true, 0.25),
    ProductionLikeAnchor(1.0, 0.05, 0.25),
], 0.25)
```

### 4.3 ContinuationStrategy

`ContinuationStrategy` 负责从一个 anchor root 沿 path 生成 branch points。

建议接口：

```julia
abstract type AbstractContinuationStrategy end

struct SeedContinuation <: AbstractContinuationStrategy
    evaluate_all_attempts::Bool
end

struct PALCContinuation <: AbstractContinuationStrategy
    ds::Float64
    dsmax::Float64
    max_steps::Int
    newton_tol::Float64
    newton_max_iterations::Int
    backend::Symbol
end
```

职责边界：

- `SeedContinuation` 是现有 scan/continuity 行为的结构化表达，可作为无外部依赖 MVP。
- `PALCContinuation` 是 PALC backend 的配置对象；类型可以进入 `src/models`，但 BifurcationKit backend 不在 MVP 进入根环境。
- 当 `backend=:bifurcationkit` 且依赖不可用时，必须抛出明确 `ArgumentError` 或 `UnsupportedCapabilityError`，不能静默 fallback。

### 4.4 BranchPolicy

`BranchPolicy` 负责多分支之间的语义选择。

建议接口：

```julia
abstract type AbstractBranchPolicy end

struct GroundStateBranchPolicy <: AbstractBranchPolicy
    pressure_gap_tol::Float64
    residual_norm_max::Float64
end

struct ContinuationBranchPolicy <: AbstractBranchPolicy
    branch_id::Symbol
end

struct AllBranchesPolicy <: AbstractBranchPolicy
end
```

语义要求：

- `GroundStateBranchPolicy` 必须按 constraints 合格后 pressure max 选 branch。
- 当 selected branch 与 runner-up 的 `pressure_gap <= pressure_gap_tol` 时，结果必须显式标记近简并选择，避免把数值噪声内的 pressure max 误读为确定性物理解。
- `ContinuationBranchPolicy` 必须保持指定 branch，不允许逐点跳到 pressure max branch。
- `AllBranchesPolicy` 返回所有 branch，不做单一物理解选择，适合诊断和画图。

## 5. 核心入口草案

首期建议作为内部实验入口，不导出稳定 API：

```julia
solve_path(
    model::AbstractQCDModel,
    path::AbstractPathProblem;
    anchor_strategy::AbstractAnchorStrategy=SeedPoolAnchor(),
    continuation_strategy::AbstractContinuationStrategy=SeedContinuation(true),
    branch_policy::AbstractBranchPolicy=GroundStateBranchPolicy(1e-3, 1e-6),
    diagnostic_level::Symbol=:summary,
    branch_jump_tol::Real=0.25,
)
```

返回：

```julia
struct PathSolveResult
    path::AbstractPathProblem
    branches::Vector{ContinuationBranch}
    selections::Vector{BranchSelection}
    anchors::Vector{AnchorRoot}
    diagnostics::PathDiagnostics
end
```

首期可先用 `NamedTuple` 实现内部结果，等字段稳定后再固化为 concrete struct。

## 7. 与现有接口的关系

### `solve` / `solve_multi`

- 保持单点语义。
- `solve_path` 可以调用 `solve_multi` 做 anchor discovery。
- 不应让 `solve(...; seed_strategy=PALC...)` 这类调用成立，因为 PALC 不是单点 seed policy。

### `SeedStrategy`

- `SeedStrategy` 只负责生成初值。
- `AnchorStrategy` 可以消费 `SeedStrategy`，但两者不是同一层抽象。

### `ProblemSpec`

- `ProblemSpec` 继续负责单点 residual/selector 主链。
- `PathProblem` 可在每个 path point 内部构造对应 `ProblemSpec` 或 residual function。
- PALC backend 需要 residual/Jacobian 时，应复用 `build_residual!` / `explicit_residual!`，避免重复物理公式。

### `run_trho_scan` / production scripts

- 短期保留脚本层 pressure-governed all-attempt 修复。
- `solve_path` 进入 experimental 后，可新增 opt-in script flag，例如 `--continuation-backend palc_experimental`。
- 默认 production path 只有在 multi-branch PALC 通过回归门槛后才能切换。

## 11. 风险与回退方案

- 风险：PALC 单分支被误用为 ground-state solver。
  - 回退：接口强制区分 `ContinuationBranchPolicy` 和 `GroundStateBranchPolicy`，报告必须包含 candidate branch count。
- 风险：BifurcationKit 编译时间过长。
  - 回退：根环境不引入依赖，先保持分析环境；若正式化，评估 sysimage/precompile。
- 风险：anchor discovery 漏根。
  - 回退：保留 `solve_multi` / MultiSeed catalog，并允许生产式 continuation root 作为 anchor source。
- 风险：结果结构过早稳定导致后续 PALC 字段难扩展。
  - 回退：首期使用内部 NamedTuple，待字段稳定后再导出 concrete result type。
- 风险：改变 production 默认路径导致数值产物漂移。
  - 回退：所有 PALC path 先 opt-in，production 默认继续使用当前 pressure-governed all-attempt scan。
