# 介子数密度 Phase D3 BW 最小设计说明

更新日期：2026-05-01

目的：在 BU 正式实现前，把 BW 过渡层严格限定为“诊断桥梁”，明确它的输入、输出、边界和验收口径，避免 D3 自身继续膨胀。

---

## 1. D3 的定位

Phase D3 不负责给出最终介子热力学结果，只回答一个更窄的问题：

- 当稳定粒子极限开始接近失效时，
- 若把介子宽度 `Gamma_M` 以最小 BW 方式纳入，
- 数密度量级、温度连续性和 `K/pi` 比值会怎样变化。

因此，D3 的角色是：

- 连接 D2 稳定粒子基线 与 Phase E BU 相移实现
- 诊断“宽度进入”本身造成的影响
- 避免把所有异常都提前归因到 BU / phase shift

## 2. 输入口径

D3 继续复用现有 meson workflow 主链，不新开平行求解链。

固定输入来源：

- workflow 入口：`Models.solve_gap_and_meson_point`
- 输入物理量：
  - `thermo_params.T`
  - `meson_results[:pi/:K].mass`
  - `meson_results[:pi/:K].gamma`
- continuation 口径：
  - 继续显式使用 `continuation_state`
  - 不允许在脚本层重新发明 seed 维护逻辑

当前最小物理窗口建议保持：

- `muB = 0`
- `xi = 0`
- `pi/K` 两道
- 温区优先覆盖：
  - D2 已验证窗口附近
  - 接近 Mott 的局部窄温区

## 3. 输出口径

D3 最小输出建议只保留以下几类量：

- `n_pi^stable(T)`、`n_K^stable(T)`
- `n_pi^BW(T)`、`n_K^BW(T)`
- `K/pi|stable`
- `K/pi|BW`
- 宽度修正相对量，例如：
  - `delta_n_pi = n_pi^BW - n_pi^stable`
  - `delta_n_K = n_K^BW - n_K^stable`
  - `delta_ratio = (K/pi)_BW - (K/pi)_stable`

不建议在 D3 直接输出：

- EOS 量
- phase shift
- Levinson 定理检查量
- 大范围 `T-muB-xi` 图组

## 4. 最小实现形式

当前建议：D3 优先做成分析层或最小 workflow 后处理层，而不是一开始就扩成完整公共模块族。

推荐顺序：

1. 先形成一份公式/实现口径说明
2. 再做一个最小分析脚本
3. 如果脚本结论稳定，再决定是否升格为 `src/relaxtime/` 公共后处理函数

原因：

- D3 的使命是验证，不是先铺 API 面
- BW 是否保留、以何种形式保留，还要看它对 Phase E 是否真正提供诊断价值

## 5. 与全仓扫描 workflow 抽象的关系

当前不建议把 D3 作为“全仓统一 scan 抽象”的试验田。

更稳妥的统一建议是两层：

- 第一层：统一扫描骨架
  - 参数网格遍历
  - resume / overwrite
  - CSV metadata / header / key 管理
  - run manifest
- 第二层：各物理 workflow 自治 continuation 状态
  - 例如 meson workflow 的 `continuation_state`
  - 不强行抽象成所有 workflow 共用的单一物理状态对象

原因：

- 不同 workflow 的 continuation 语义不一样
- 真正高复用的是“扫描壳层”，不是“物理状态内容”
- 若把两者过早绑死，后续很容易为了统一而扭曲具体物理链路

## 6. D3 的验收标准

D3 最小通过标准建议为：

- 能明确跑出稳定极限与 BW 的对照结果
- 能说明宽度进入后，哪些变化是连续的、可解释的
- 能指出 BW 相比稳定极限新增了什么
- 能明确指出 BW 仍然缺少什么，为什么它不能替代 BU

更具体地说，D3 文档或输出中至少应回答：

- 在接近 Mott 的窄温区，BW 是否能避免稳定极限的直接失效
- `K/pi` 比值在 BW 下是否出现与稳定极限显著不同的趋势或偏移
- 这些差异是否足以支撑进入 Phase E

## 7. D3 不应承担的任务

以下内容应明确留给 Phase E 或更后阶段：

- 从传播子/极化函数严格构造 `delta_M(omega)`
- Levinson 定理层面的完整自洽
- continuum / bound-state 统一处理
- EOS 推导
- 对文献结果的最终物理解读

## 8. 下一步实现建议

下一步若进入实现，建议次序为：

1. 先补一页 BW 公式口径说明
2. 再做最小分析脚本，固定少量温点或窄温区
3. 只比较 stable vs BW
4. 验证它是否确实提供了进入 BU 前需要的诊断信息

若第 4 步结论不强，应停止扩张 D3，直接转向 Phase E 的相移设计。
