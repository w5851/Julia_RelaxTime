# src 10维度结构化体检报告（2026-03-27）

## 1. 背景与目的

本报告用于对 `src/` 做非性能单一视角的结构化审查，覆盖以下 10 个维度：

1) 正确性与数值稳健性  
2) API 与语义一致性  
3) 架构与模块边界  
4) 可测试性与验证完备度  
5) 可维护性与可读性  
6) 配置治理与可复现性  
7) 并发与状态安全  
8) 观测性与诊断能力  
9) 工程治理与交付质量  
10) 安全与健壮性

结论仅基于仓库代码/文档证据，不包含实现改动。

## 2. 总览结论

- 最高优先风险：`pnjl_scan_jobs` 的 `output_path` 写路径边界（P0）。
- 高优先改进：scan jobs 测试补齐、文档旧路径清理、配置复现元信息增强（P1）。
- 中优先改进：大文件维护性拆分、诊断字段结构化（P2）。

## 3. 分维度体检结果

### 3.1 正确性与数值稳健性

- 现状：`TransportCoefficients`/`RelaxationTime` 已有输入校验、非负钳制与 NaN/Inf 防护。
- 风险：
  - 扩散积分核与同文件 η/σ 写法存在不一致。
  - `safe_inv(0)=Inf` 的语义需上游明确承接。
- 证据：
  - `src/relaxtime/TransportCoefficients.jl:920`
  - `src/relaxtime/TransportCoefficients.jl:974`
  - `src/relaxtime/TransportCoefficients.jl:1211`
  - `src/relaxtime/RelaxationTime.jl:410`
- 优先级：P1
- 下一步：先补一条扩散核契约测试，明确该处是否设计预期。

### 3.2 API 与语义一致性

- 现状：`Struct + NamedTuple` 双路径兼容较完整，workflow 兼容逻辑清晰。
- 风险：
  - 文档仍存在旧路径 `src/pnjl/...`，与当前主线 `src/models/...` 不一致。
  - 兼容别名长期保留会造成接口认知分叉。
- 证据：
  - `src/relaxtime/RelaxationTime.jl:203`
  - `docs/api/PARAMETER_TYPES_API.md:602`
  - `docs/guides/PARAMETER_STRUCT_MIGRATION.md:24`
- 优先级：P1
- 下一步：做一次 docs 路径口径统一，并标注兼容别名退场节奏。

### 3.3 架构与模块边界

- 现状：`TransportWorkflow` 作为编排层边界明确。
- 风险：
  - 大量 `Main.*` 直接耦合，增加模块隔离与复用成本。
  - include 兼容提升扩大了全局命名面。
- 证据：
  - `src/models/workflows/TransportWorkflow.jl:26`
  - `src/models/workflows/TransportWorkflow.jl:67`
  - `src/relaxtime/RelaxTime.jl:10`
- 优先级：P2
- 下一步：先引入依赖注入薄封装，收敛 `Main.Models` 直连点。

### 3.4 可测试性与验证完备度

- 现状：配置加载、workflow、relaxtime 主链有较好测试覆盖。
- 风险：
  - `fullserver/pnjl_scan_jobs.jl` 缺少对应自动化测试。
  - HTTP 参数/状态码契约缺少回归护栏。
- 证据：
  - `tests/unit/config/test_config_loader.jl:145`
  - `tests/unit/models/test_transport_workflow.jl:33`
  - `src/simulation/fullserver/pnjl_scan_jobs.jl:363`
- 优先级：P1
- 下一步：新增 `tests/unit/simulation/test_pnjl_scan_jobs.jl` 最小契约集。

### 3.5 可维护性与可读性

- 现状：关键流程有 helper 拆分，但核心文件体量偏大。
- 风险：
  - 超长文件降低审阅与定位效率。
  - 接口层与数值细节混合，变更影响面较大。
- 证据：
  - `src/models/workflows/TransportWorkflow.jl`
  - `src/relaxtime/AverageScatteringRate.jl`
  - `src/relaxtime/TransportCoefficients.jl`
- 优先级：P2
- 下一步：优先拆分 `TransportCoefficients` 为“校验/适配/积分核”子模块。

### 3.6 配置治理与可复现性

- 现状：`ConfigLoader` 已有内容哈希缓存、命中统计、防污染返回。
- 风险：
  - 结果受 `PHYSICS_PARAM_PROFILE` 环境变量影响，需显式落盘。
  - TOML 解析失败 fallback 仅 warning，若未被观测会静默继续。
- 证据：
  - `src/config/ConfigLoader.jl:197`
  - `src/config/ConfigLoader.jl:224`
  - `src/models/workflows/TransportWorkflow.jl:186`
  - `docs/guides/configuration.md:27`
- 优先级：P1
- 下一步：在 workflow 结果补充 profile/path 元信息，便于复现归档。

### 3.7 并发与状态安全

- 现状：配置缓存与 scan jobs 全局状态均有锁保护，并用 semaphore 限流。
- 风险：
  - `_PNJL_SCAN_JOBS` 长期运行只增不减，存在内存累积风险。
  - 高频进度回调可能形成锁争用热点。
- 证据：
  - `src/simulation/fullserver/pnjl_scan_jobs.jl:4`
  - `src/simulation/fullserver/pnjl_scan_jobs.jl:139`
  - `src/simulation/fullserver/pnjl_scan_jobs.jl:245`
- 优先级：P1
- 下一步：增加 TTL/数量上限清理策略，并补对应单测。

### 3.8 观测性与诊断能力

- 现状：已有 warning、cache stats、scan 状态与进度信息。
- 风险：
  - 缺统一结构化诊断字段（job_id/profile/T/mu/xi）。
  - 部分失败路径仅 warning，缺计数化指标。
- 证据：
  - `src/config/ConfigLoader.jl:170`
  - `src/models/workflows/TransportWorkflow.jl:611`
  - `src/simulation/fullserver/pnjl_scan_jobs.jl:425`
- 优先级：P2
- 下一步：定义最小结构化日志字段约定并在关键路径统一。

### 3.9 工程治理与交付质量

- 现状：主链路 CI/测试门禁较完整。
- 风险：
  - 文档路径不一致影响交付一致性。
  - scan 服务链路测试缺位影响质量下限。
- 证据：
  - `docs/api/PARAMETER_TYPES_API.md:602`
  - `docs/guides/PARAMETER_STRUCT_MIGRATION.md:31`
  - `src/simulation/fullserver/routing.jl:13`
- 优先级：P1
- 下一步：把 docs 路径一致性与 scan jobs 基础测试纳入常规治理检查。

### 3.10 安全与健壮性

- 现状：请求参数有基本范围校验，异常可回传 JSON。
- 风险：
  - `output_path` 允许请求直接指定，缺少安全根目录约束。
  - 对外错误详情可能包含过多内部信息。
- 证据：
  - `src/simulation/fullserver/pnjl_scan_jobs.jl:192`
  - `src/simulation/fullserver/pnjl_scan_jobs.jl:228`
  - `src/simulation/fullserver/pnjl_scan_jobs.jl:348`
  - `src/simulation/fullserver/pnjl_scan_jobs.jl:480`
- 优先级：P0
- 下一步：限制写路径到 `data/outputs/...` 安全子树，并将对外错误降级为错误码+摘要。

## 4. 优先级建议（低风险高收益 Top 3）

1. P0：scan `output_path` 安全收口（路径白名单 + 规范化校验）  
2. P1：补 `pnjl_scan_jobs` 最小契约测试  
3. P1：清理 docs 中旧 `src/pnjl` 路径引用
