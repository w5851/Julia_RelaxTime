# Document-driven Implementation

## Hard rules

- 优先使用用户指定文档；否则在 `docs/dev/active/` 中定位最匹配的活动文档。
- 默认连续执行，只有真实阻塞、严重偏离或需要关键用户决策时暂停。
- 每个任务项完成后核对主线目标、仓库结构和治理规则。
- 每步运行与风险匹配的验证；无法自动验证时记录原因和风险。
- 任务状态、实现结果、验证证据和最终汇报必须一致。
- 不因普通执行进度自动创建执行台账；只有文档或用户明确要求时才使用 `doc-exec-log-append`。

## Workflow

1. 读取目标活动文档、相关入口、对应测试层和仓库治理规则。
2. 确认下一个未完成任务、依赖、非目标和验收条件。
3. 实现最小收敛变更，保留用户已有的无关改动。
4. 运行聚焦验证，必要时扩大到 profile、回归或治理检查。
5. 只在验证满足验收条件后更新任务状态。
6. 重复推进，直到任务完成、出现阻塞或用户改变主线。

## Blocking conditions

- 无法可靠确定目标活动文档；
- 文档与当前代码、目录或稳定契约发生实质冲突；
- 缺少关键依赖、权限或必须由用户作出的语义选择；
- 继续执行会扩大文件范围、风险或外部影响。

遇到阻塞时，说明证据、影响、已经尝试的替代路径和需要用户决定的最小问题。

## Final report

汇报完成项与文件、验证结果、任务单状态更新、主线偏差、未完成或阻塞项以及基于当前文档的下一步。
