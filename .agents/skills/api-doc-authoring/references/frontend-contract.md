# 前后端契约检查

配合计算 API 的通用字段要求，补充前端实际消费接口时容易遗漏的边界。接口位置与服务职责见[API 导航](../../../../docs/api/README.md)，稳定说明写入对应 API/脚本页面，未实现的对接方案留在已有开发设计中。

- **调用边界**：区分 Julia 计算入口、脚本输入输出和 HTTP 路由。沿实际解析、参数转换与返回映射核对字段；有计算函数而无服务适配时明确缺口。
- **有效请求**：记录省略字段、显式空值、默认值与配置覆盖的实际区别，以及单位换算发生的位置。请求示例应能到达目标计算，不能只满足 JSON 外形。
- **数值对应**：说明响应数组的维度、轴顺序、坐标/通道/分支标识和排序；缺失点、无穷值或未收敛值如何序列化，以实现为准，不能假定都变为零或 `null`。
- **失败与部分结果**：分别说明实际存在的参数拒绝、求解失败、空结果和部分成功；核对 HTTP 状态码与响应体中的计算状态，避免将请求成功解释为数值有效。
- **异步任务**：仅在接口确实使用 job 时说明任务标识、状态查询、结果就绪条件，以及已实现的取消/超时边界；不为同步接口虚构状态机。
- **可用性证据**：提供最小成功请求/响应及相关边界示例。区分从实现核对、契约测试验证和实际服务调用验证；mock 或未执行示例明确标注，不把已配置写成已联通。

选择现有路由、处理器或服务契约测试核对受影响部分。仅编写说明无需自动部署服务、增加新接口或重新运行整套科学扫描。
