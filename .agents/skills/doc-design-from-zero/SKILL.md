# Development Document Design

## Boundary

- 只设计可执行文档，不把未实施内容标为完成。
- 缺失信息时采用最小可行假设并显式标注。
- 默认落点为 `docs/dev/active/`，命名遵循 `docs/dev/README.md`。

## Required inputs

- 功能目标与背景
- 范围和非目标
- 相关公式、接口、模块与规范
- 质量、性能、测试和回归要求

## Document structure

1. 背景与目标
2. 范围与非目标
3. 当前能力与缺口
4. 可勾选任务分解
5. 测试与验收标准
6. 里程碑
7. DoD
8. 风险与回退方案

只在有事实证据时使用 `- [x]`；其余任务保持 `- [ ]`。

## Workflow

1. 从仓库现状提取约束和权威入口。
2. 把目标拆成实现、验证、文档和治理任务。
3. 为每项写清动作、依赖和完成信号。
4. 区分 MVP、后续增强和明确非目标。
5. 检查路径、术语、状态和测试层的一致性。

## Quality gate

- 每项任务可执行且可验收。
- 里程碑能映射到任务和验证证据。
- 风险包含可操作的缓解或回退方案。
- 文档不预先承诺尚未验证的数值或性能结果。
