# 正式数值产物

选择 [SOP 索引](../../../docs/guides/sop/README.md) 中的目标专题，按[公共科学计算生命周期](../../../docs/guides/sop/common_scientific_run.md)及该专题的入口、精度标准和产物合同执行。

先定位已有结果、精度证据和本次输入差异，按证据缺口读取公共 SOP 的相关章节及专题规则。引用有效的既有确认，并在现有任务记录中维护状态。

## 根据现有证据选择工作

- **已有候选结果且证据齐备**：核对本批实际数据及 provenance，直接进入晋升验收；不因目录名或缺少一次名为 production 的运行而机械重跑。
- **已有结果但证据不足**：说明哪些证据仍有效、哪些因代码/配置/输入或参数域变化而失效；按公共 SOP 的复用条件只补受影响的比较、失败点诊断或验证。需要改变有效配置时生成新 case。
- **尚无所需结果**：使用已获精度证据支持的配置生产，再验收实际产物。

参数精度获支持与本批结果达到正式标准是两个判断。最终状态依专题和公共 SOP 的晋升条件确定，包括所需的物理口径确认；任务授权与既有确认沿用当前会话。

## 执行与产物

1. 明确目标观测量、参数域、有效配置及源代码/输入版本，链接适用的收敛和验证证据。
2. 按用户选择与专题 SOP 使用稳定本地入口或已注册的 GitHub Actions。使用 Actions 时核对 workflow、实际执行 ref 和输入均支持目标 case；下载后记录 run URL、head SHA 和 artifact 来源。
3. 数值、配置、日志与审计放入 `data/outputs/results/`；图像及 `plot_manifest.json` 放入 `data/outputs/figures/`。沿用工作流已有 manifest/summary，保留冻结产物与原始证据。
4. 核对本批输出的有效配置、完整性、失败点、分支/通道状态和专题要求的 regression/validation。运行成功只证明产物生成，正式状态在这些检查后判定。
5. 需要作图时使用 `plotting-sop`，让图像反向关联已验收的数值来源。

## 交付

在既有结果说明和 manifest 中记录产物位置、证据引用、实际完成的验证及本批状态。没有达到正式标准时说明具体缺口；达到标准时交付来源可追踪的结果和图表，不另造多份相同内容的审计文档。

数值验收、产物晋升与论文使用资格分别沿用对应 SOP 和已确认的作者决定；某一项通过不自动授予另外两项。
